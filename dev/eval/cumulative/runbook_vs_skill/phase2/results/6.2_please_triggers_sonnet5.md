## Step-scoring recount (added 2026-09-20)

Question: is the 10/19 (vs 19/19 in two 3.3d trials) real, or a scorer artifact? The Caveat above guessed "subagent transcripts invisible". That guess is WRONG: the 6.2 run was scored live, and live scoring already reads main + subagent transcripts (`discover_transcript_paths` globs `**/*.jsonl` recursively). Recounting with the harness's own `evaluate_steps` over main only, main + `<sid>/subagents/*.jsonl`, and everything gives the same 10/19 for all 3 trials (script: a throwaway that imports `probe_phase2.evaluate_steps`; no harness change). Contrast 3.3d trials 0 and 2: main-only 11 and 10, main + subagents 19. So subagents matter for 3.3d but not here.

Real cause, a scorer signal gap plus an ordering cascade:
- Step 10 (RED: test file edited first) only recognizes an Edit/Write/MultiEdit on `tests/test_tally.py` or `sed/perl -i ... test_tally.py`. In all 3 trials the TDD subagent (or the main agent) edited the test file with a `python3 - <<EOF ... open("tests/test_tally.py","w").write(...)` heredoc, which no signal matches. The 3.3d passing trials used Edit/sed.
- Steps 11-18 each carry `after: <previous step>`, so one miss at step 10 fails 11, 12, ... 18 (9 steps: 10-18). Step 19 has no `after`, so it passes.

Check: with the `after` constraints removed (same evaluator, same events), 6.2 scores 18 / 18 / 17 of 19. Only step 10 misses (all 3), plus step 18 in trial 2.

| Trial | recorded /19 | main only | main+subagents | missing (recorded) | missing with `after` removed | what those steps really did |
|---|---|---|---|---|---|---|
| R-0 | 10 | 10 | 10 | 10-18 | 10 | test edit via python heredoc in TDD subagent; then tally.py Edit, pytest, docs Edits (docs subagent), Gate C x2, Gate D, commit, `engram ingest --auto`, lessons audit all present |
| R-1 | 10 | 10 | 10 | 10-18 | 10 | same shape (heredoc + `sed -i` in TDD subagent) |
| R-2 | 10 | 10 | 10 | 10-18 | 10, 18 | test edit via heredoc in subagent; step 18 real minor miss: closing report has "lessons audit", STOP, FAIL, CORRECTION but says "escalate", not the word "escalation" |

Steps 1-9 (opening /learn, recall, grep, plan commit, all four Gate A reviewers, recall-first handoff) were hit in all 3; the opening /learn was `engram ingest --auto`, and the closing one was too. Nothing was skipped: gates A/B/C/D, plan commit, lessons audit all ran (gates run as Agent dispatches in the main transcript; their bodies in subagents).

Conclusion: ARTIFACT, but not the subagent one. It is a brittle step-10 signal (python-heredoc test edits invisible) amplified by the `after` chain. No evidence the trigger or `--text` changed what the agent does after retrieval; the agent followed the whole workflow. Genuine minor residue: R-2 step 18 wording ("escalate" vs "escalation"). Note: the 3.3d jsonl lists trial 1 (the runbook-miss trial, 0/19) first, so line order differs from trial number.

Scorer bug, described not fixed: `evaluate_steps` step 10 has no python-write signal, and a single missed step fails every later `after`-chained step, making followed_k jump 10 <-> 19 on edit-tool choice rather than behavior. Also `--rescore` parses only the main transcript (already noted in 1.3). Suggested fix (needs Joe's OK): add a `bash_regex` for `open\(["']?tests/test_tally\.py` heredocs (and treat step 10 alternatives in steps 11's `tally.py` similarly), then rescore 6.2 with `--rescore` over main+subagents.
