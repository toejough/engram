# 6.1 `--text` fidelity, headless RED/GREEN (sonnet5), 2026-09-20

## Method
Reused the 3a.3 runner (`3a3_phrase_two_red_green_runner.py`): each trial is a fresh headless `claude -p` (claude-sonnet-5) in an isolated CLAUDE_CONFIG_DIR (global `~/.claude/CLAUDE.md` and its deployed-shim import NOT loaded), project CLAUDE.md = the arm's shim + a per-trial marker, no skills, a tiny fictional repo, a copy of the real vault as the trial vault (queries only, run killed right after the first `engram query` is issued). Only the first `engram query` is scored. Runner/scorer copies: scratchpad `w61/` (runner61.py, score.py, results.jsonl).

Arms differ ONLY by the `--text` block-line and its one sentence (diff of GREEN=current `agent-instructions/guidance/shim.md` vs RED):
```
21d20
<   --text "<the user's message, word for word>" \
26,28d24
< 
< `--text` is the user's message pasted verbatim (its first ~300 characters if long), never rewritten or
< summarized; your paraphrase goes only in `--phrase`.
```
The phrase-two re-check paragraph is kept in both arms.

Design note: the design says '5 asks x 3 trials x 2 arms = 30' but bar 'GREEN >= 27/30'; to match the bar denominator each arm has 30 trials (5 asks x 6 trials).

Scoring (deterministic, on the shell-parsed args of the first query): (a) has a `--text` arg; (b) value contains the ask verbatim (asks > 300 chars: first 200 chars verbatim), STRICT substring including whitespace/newlines; (c) not the shim's example text. Also reported: whitespace-normalized (b).

## Validity gates

- 60 runs, 0 errored/degenerate/discarded. Every run issued an `engram query` as its first query; first tool call was the query in 59/60 (1 RED run ran another tool first).
- Contamination: transcripts checked for the shim's `--text` sentence ("pasted verbatim") and example line ("word for word"). GREEN: present in 30/30 and 30/30. RED: 0/30 and 0/30. (2 pilot trials, special-0 both arms, had their transcripts overwritten by a pool rebuild; for those the check used the arm's CLAUDE.md, which is what the agent was given.) Global CLAUDE.md not loaded (isolated config dir, same as 3a.3).
- RED first queries retain both `--phrase` values (30/30 have 2 phrases) so RED is a fair comparator.

## Failure analysis
- special 5/6 fail: the agent pasted the message verbatim EXCEPT it replaced the literal newline with a space (all other characters incl. backticks/quotes/backslashes/`$` intact). Strict substring fails; whitespace-normalized passes.
- e2e 1/6 fail: the agent dropped the leading `Please take this end-to-end:` and pasted only the task body. This is a genuine miss and hits exactly the phrase the please trigger keys on.
- All 30 GREEN values had a `--text`; none copied the shim's example text. RED emitted `--text` 0/30, so the shim line is the causal lever.

## Spend
60 runs, harness-reported/estimated total $3.24 (runs are killed after the first query, so figures are token estimates). Under the ~$10 cap.

## Read and fix options
Read: the instruction works (0/30 -> 30/30 has `--text`), but 'word for word' is read as permission to tidy: newlines flatten and, once, a leading politeness/handoff prefix is stripped as 'framing'. Fix options (full text; do NOT rerun without Joe's OK):
1. Sentence text: "`--text` is the user's message pasted verbatim, character for character, from its first character (its first ~300 characters if long): keep the opening words and slash commands even if they look like framing, and keep line breaks. Never rewrite or summarize; your paraphrase goes only in `--phrase`."
2. Tell the agent the matcher is lexical, so the opening words are exactly what matters: "`--text` is matched literally against runbook trigger phrases, so start it at the user's very first character."
3. Make the newline case moot: engram query normalizes whitespace in `--text` before matching (harmless for phrase triggers); then only the e2e prefix drop needs the wording fix. Under normalization this run's GREEN is 29/30.
4. If wording still leaves misses: the prompt-submit hook follow-on (task 6.4).

## Bar amendment (2026-09-20)

Original bar: strict verbatim `--text`, GREEN >= 27/30. Measured: strict 24/30, whitespace-tolerant 29/30, RED 0/30 both; contamination gate passed. Joe amended the bar to whitespace-tolerant verbatim after seeing this result, because the matcher (`internal/cli/query_triggers.go`) lowercases and collapses whitespace runs on both sides, so whitespace differences cannot affect a trigger match. Shim wording stays as deployed. Of the 6 strict misses, 5 were whitespace-only (newline flattened to a space, all on the quotes/backticks/newline ask). The one real miss (1/30) dropped the opening 'Please take this end-to-end:' prefix, the cue a trigger keys on: known residual risk, unfixed by choice. The result above is preserved unchanged.
