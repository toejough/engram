# 5.0 register-skills-as-runbooks adoption retrieval check (task 3.5, no LLM spend)

Change `register-skills-as-runbooks`, task 3.5 (design D6, D10). Date 2026-09-26. Read-only: `engram query` / `engram show` / `engram check` only, no vault writes.

## Method

- **now** = the live real vault `~/.local/share/engram/vault` after adoption (`1036.2026-09-18.skill-route`, `1045.2026-09-20.skill-please`, `1049.2026-09-21.skill-curate`, `1053.2026-09-22.skill-write-memory`; please sub-notes 1042/1043/1044 removed).
- **before** = the same vault at pre-adoption commit `8ca9488`, exported read-only (`git -C <vault> archive 8ca9488 | tar -x` into a scratch dir; sidecars are tracked, so the export has its own pre-adoption `.vec.json`). Both runs use the same installed binary (`~/go/bin/engram`), the same default chunk index, cwd `~`, and `engram query --lazy-chunks --vault <v> [--limit N] [--text T] --phrase P ...`. Measuring before and now on the same day, same binary, same vault differs by exactly the adoption.
- **expected** quotes what the source retrieval check recorded. Where that check ran in a trial vault (please 3.1, curate 3.1), its recorded rank is not directly comparable to the real vault; the before/now pair is the regression test, the recorded value is context.
- Rank = position in `items[]` (chunks included), `[id]` = the note that matched, then score and provenance. "absent (N)" = not among the N items returned.
- Sidecar diff: for all four notes `situation_vector` is byte-identical before/now and `body_vector` differs (new body = restored `SKILL.md`). Wherever the situation drives the match, scores are identical to 8 digits.
