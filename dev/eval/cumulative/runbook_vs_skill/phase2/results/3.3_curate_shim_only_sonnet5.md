## Harness issue (fixed, minimally, under phase2/ only)
The smoke's live end_state was FAIL although the agent did everything right. Cause: `--shim-only` adds the recall/learn/write-memory carrier (8 notes, ids 1-8, dated 2026-09-14) plus the curate runbook (id 10) to the vault, and `fixtures/curate/done_when_checks.sh` (written for S/N arms) required the note-id set to be exactly {1..6, 9} and looked notes up by bare id, which would also match the carrier's colliding ids. Fix: the checker now resolves fixture notes by their `2026-09-20` date and excludes the known carrier basenames (`encodings/shim/recall-learn/vault`, `encodings/taskCurate/Curate-R/vault`) from the note-set check; a stray `engram learn` note still fails. Test added (`test_curate_done_when_ignores_the_shim_only_arm_carrier_notes`); 37 curate tests pass. The smoke was rescored (`--rescore`) to PASS; the n=3 ran with the fixed checker (end_state is live, not rescored). Side observation, agent behavior not a harness bug: in the smoke, bare `--target 3` / `--target 2` resolved to the colliding 2026-09-14 carrier notes (an extra activation on note 3.2026-09-14); the agent noticed and redid with full basenames. In the 3 n=3 trials all agents used full basenames from the start. The id collision is an artifact of the synthetic vault, not of the runbook.
