## Why trial R-0 failed end_state despite followed_all=True

`done_when_checks.sh` output: `FAIL: vault note ids are [qa qa 1 2 3 4 5 6 7 8], expected [1 2 3 4 5 6 7 8]`.

The transcript shows the agent correctly wrote the two required notes (`7...printer3-corner-warping-bay-door-draft.md`,
tag `component/cooling`; `8...printer-bay-circuit-trip-simultaneous-preheat.md`, tag `component/electrical`), then
made an unrequested third call: `engram learn qa --slug printer3-corner-warping-most-likely-cause --question ... --answer ...`.
That single command writes **two** vault files (`qa....q.md` and `qa....a.md`), which is what produces the
duplicate `qa qa` entry in the failure output. The task's done_when explicitly required "exactly one new note
for the draft/warping finding and one for the breaker rule, nothing else written or removed" — the extra qa
capture (learn's own "capture uncaptured substantive Q&A" step, applied to the diagnostic question the agent
itself posed and answered) violated that. This is a task-fidelity/over-capture failure, not a runbook-fetch or
tag-flag failure — the validity gate held and both required writes were correct.
