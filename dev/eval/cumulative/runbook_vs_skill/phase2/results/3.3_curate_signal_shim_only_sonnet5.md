## Where R stops (all 3 trials alike)
1. First tool call is `engram query --lazy-chunks --text ... --phrase ... --phrase ...` (shim followed). The binary printed `pending_offers: true` and `pending_offers_hint: run ...` (verified in the persisted payload, 3/3), but the payload was 94-112 KB, so the harness showed only a preview and saved the rest to a file. The agent grepped that file for `situation` lines, never the tail, so it never saw the signal (0/3). Hint at the END of a very large payload is a delivery weakness for the query-side signal in this vault size.
2. Agent read the recall/learn/write-memory runbooks (`engram show`), wrote the note with `engram learn`, and got the write-path warning containing the hint command (3/3).
3. Each then declined: "I didn't touch them since you didn't ask, but I can run the curate runbook if you want" (3/3). No trial ran the hint's `engram query --text "curate pending offers"`, so the curate runbook body was never fetched (its path appeared only in the grep-listed payload).

The same "outside the request, offer to do it" reasoning appears in S and N, so it is not a runbook-vs-skill difference; it is how the agent treats an optional-sounding warning during an unrelated ask.
