## Tag-flag observation

All 3 trials used the correct singular, repeatable `engram learn ... --tag <family>/<value>` flag on
both writes — never the plausible plural `--tags` mistake. Since write-memory is a real skill here (its
own SKILL.md documents `--tag` correctly), this is a genuine skill-following result, not a runbook-
fidelity question: the skill arm gets the flag right 6/6 writes. This is the reference point section 3's
shim-only arm will be compared against on the same divergence.

## A secondary observation: `learn`'s own Skill-tool invocation was inconsistent

`recall` and `write-memory` were explicitly invoked via the `Skill` tool in all 3 trials. `learn` was
explicitly invoked via the `Skill` tool in only 1/3 (trial 1) — in trials 0 and 2, the agent composed the

"present and used," and `learn`'s own explicit invocation was not consistent across trials even though its
prescribed behavior (unconditional write on an explicit save-request) was followed every time.

## Harness bug found and fixed (steps.json, not agent behavior)

The live run's raw scores showed `followed_all=false` for trials 1 and 2 (7/10 and 8/10), both missing
exactly steps among {4, 6, 8} — the "correct `--tag`", "`--situation` present", and "correct `--tag`
(breaker)" checks. Inspecting the real transcripts showed both writes used the correct `--tag` flag and
carried `--situation`; the miss was a scoring bug: steps 4/5/6/8/10's same-command lookahead scope
(`(?:[^;&|\n\\]|\\\r?\n)*`) excludes a bare `;`, intended to stop the scope at a shell-chained command
boundary, but a real `engram learn` command's own quoted prose legitimately contains English semicolons
(e.g. "...vault memory; synthesis (abduction)...", "...two-minute window; stagger printer startups...").
When such a semicolon fell between the warp/draft (or breaker/preheat/trip) keyword and a later flag the
step also required, the lookahead broke and the step scored `False` on a fully compliant command.

Fix: removed `;` from the exclusion class in `fixtures/write-memory/steps.json` (`[^;&|\n\\]` ->
`[^&|\n\\]`), keeping `&`/`|`/raw-newline exclusion (real chaining/multi-command boundaries) intact. Added
three regression tests to `test_probe_phase2.py` reproducing the exact live-trial commands (RED before the
fix, GREEN after), plus a guard test confirming the fix does not blunt the `--tags`-vs-`--tag` divergence
steps 4/8 exist to catch. Re-validated by hand against TASK-RATIONALE.md's three documented synthetic-
transcript properties, unaffected by the fix: ideal transcript 10/10; a `--tags`-mutant transcript fails
exactly steps 4 and 8; a transcript missing the breaker write fails exactly steps 7-10. Full suite:
454 passed, 2 skipped (was 451 passed, 2 skipped before the two RED tests were added). No trial was
rerun — this is a pure transcript-scoring fix, so the existing kept transcripts were re-scored with
`--rescore` (zero additional cost); the `.rescored.jsonl` file has the corrected `followed_all`/
`followed_k` used in the table above. Live (pre-fix) values, for the record: trial 0 10/10, trial 1 7/10
(missed 4,6,8), trial 2 8/10 (missed 4,8).
