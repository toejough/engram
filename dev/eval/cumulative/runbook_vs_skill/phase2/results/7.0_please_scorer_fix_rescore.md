# 7.0 please scorer fix: rescore of every kept please transcript (2026-09-20)

Why: the 6.2 recount (see 6.2_please_triggers_sonnet5.md, "Step-scoring recount") found step 10 of fixtures/please/steps.json

## What changed (harness only; no results file, jsonl or LEDGER edited)

1. New signal `bash_writes_file` in probe_phase2.py (`_write_starts`): a Bash command counts when it WRITES a path
   matching the step's regex via `sed -i`, `perl -pi`, a `>` / `>>` redirect whose target is that path, `tee [-a] path`,
   python `open(path,'w'|'a'|'x'|'r+')`, `Path(path).write_text/bytes`, or a variable bound to the path
   (`p='x'` then `open(p,'w')` / `p.write_text`). Read-only uses (cat, grep, pytest, `cat f |`, `open(p)`, `open(p,'r')`,
   a redirect to some other file, `tee` of another file) do not count. `after` ordering works as for `bash_regex`.
2. fixtures/please/steps.json: the `sed/perl -i` bash_regex alternative was replaced by `bash_writes_file` in
   step 10 (tests/test_tally.py), step 11 (tally.py; the path regex excludes test_tally.py) and step 13 (README.md,
   docs/*.md, CHANGELOG.md, tally.bash). Steps 12 and 14-19 have no file-edit signal, so nothing to change there.
   Other tasks' steps.json are untouched (their behavior is unchanged).
3. `--rescore` (rescore_file): when the recorded main transcript exists it now also parses the subagent transcripts
   beside it (`<session>/**/*.jsonl`), as live scoring does. When the recorded path was missing it already rediscovered
   all transcripts; every please record here took that path, so the earlier rescore difference (1.3 note) came from
   the existing-main-only branch. No other semantics changed.
4. Tests: 27 new tests in test_probe_phase2.py (12 write forms credited, 12 read-only forms rejected, impl-vs-test path
   separation, `after` ordering, a please step-chain test, and a rescore-includes-subagents test). RED seen first
   (unknown signal), then GREEN. Whole phase2 suite: 381 passed, 1 skipped.

## Conclusion

- Units: followed_k out of 19 steps, per trial, `after` chain intact.
- Runbook (6.2, 3 trials): 10, 10, 10 -> 19, 19, 18 (+9, +9, +8); followed_all 0/3 -> 2/3. The one remaining miss
  (trial 2, step 18) is a real wording miss ("escalate", not "escalation").
- Skill arm (1.3, 3 trials): 4, 1, 6 -> 4, 1, 6 (change 0, 0, 0). Bare arm: 4, 4, 4 -> 4, 4, 4. Shim-only 3.3 / 3.3c /
  3.3d: change 0 in every trial (the passing ones already reached 19 via Edit/sed; the rest scored 0-1 for never
  engaging).
- Even-handed? Yes. The fix credits a test/impl/docs edit whichever tool the agent used, so it moves only trials whose
  edit was a Bash write; in the kept data that is exactly the 3 trials of 6.2. It does not flatter the runbook at the
  skill's expense: the skill trials stall before step 10 (S-1 and S-2 miss the gate-A reviewers, S-0 stops after step 1),
  so no scorer change could add credit there, and with the `after` chain removed the skill row is identical before and
  after (17, 15, 18 per-step hits). The ordering of the arms is the same under either scorer in the earlier direction:
  skill 4/1/6 of 19 and 0/3 followed_all, versus the corrected 6.2 runbook 19/19/18 and 2/3 followed_all. The old 10/19
  was the scorer undercounting the runbook, not a difference in behavior.
- Caveat: the no-after figures count steps hit anywhere in the run irrespective of order (a looser measure); use the
  `after`-chain figures for ordering claims.
