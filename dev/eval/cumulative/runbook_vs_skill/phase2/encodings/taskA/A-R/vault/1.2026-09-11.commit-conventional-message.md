1. Check VCS type: look for a .jj directory; if this is a jj repo, use jj commands, not git, for the rest of this procedure.
2. Check state: run git status, git diff --staged, git diff. If there is nothing to commit, report that and stop. Note what is staged vs unstaged.
3. Review recent commits for style: run git log --oneline -5.
4. Stage changes: stage files relevant to the current change; prefer specific file paths over git add -A; do not stage unrelated files.
5. Compose the commit message in this format: type(scope): description, blank line, why we made this commit (the motivation, what problem it solves, how it fits the bigger picture, what decisions were made, and any lessons learned future developers should know; context and rationale, not just a summary of what was done), blank line, AI-Used: [claude]. Common types: feat, fix, refactor, test, docs, chore. TDD-phase message formats: TDD Red maps to test(scope): add tests for feature; TDD Green maps to feat(scope): implement feature; TDD Refactor maps to refactor(scope): cleanup.
6. Commit: run git commit -m with the composed message as a heredoc, ending with the AI-Used: [claude] trailer.
7. Verify: run git log -1 and git status.

Rules to hold throughout: The AI-Used trailer is exactly AI-Used: [claude], NOT Co-Authored-By. Never amend pushed commits; check git status for ahead of first. Separate concerns: do not mix functional changes with lint/style fixes in the same commit. First line under 72 chars; body wrapped at 72 chars. Stage specific files: do not use git add -A or git add with a bare dot. Never use dangerous commands: no discarding local changes with a checkout of dash dash dot, no restoring with a bare dot, no hard reset.
