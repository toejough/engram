## Why

Five independent defects were found in the `dev/eval` Python eval-tooling surface while running audits and probes (#787, #754, #749, #750, #755). Each one silently corrupts a measurement rather than failing loud: an audit instrument's CLI invocation drops error text and leaves "memory existed" fields empty; a scorer regex misses a valid, commonly-used invocation form and mis-scores a genuine success as a failure; a warm-config builder silently produces a skill-less config (the same bug class already fixed once, in a sibling function, by `eval-warm-config-fidelity` — but not here, since that fix was deliberately scoped to the one confirmed-broken function); a vault-leak guard false-alarms on the orchestrating session's own writes, costing an investigation for nothing; and a question-stop scorer can't tell a trailing follow-up question asked *after* a trial fully completed and verified its task from a genuine pre-completion stop. All five were found during real audit/probe runs, not hypothesized — each has a reproducible trigger and (except #750, a false-positive design gap) a concrete fix direction Joe has already decided. Fixing them now, in one batch, prevents each from continuing to quietly bias eval results that other work (including the future #710 Go port of this tooling) will build on.

## What Changes

- **#787** — `dev/eval/audit/audit_moments.py`'s `_run_engram_query_at_moment` builds its `engram query` invocation with `--phrase <value>` / (none currently use `--text`); a phrase value that itself starts with `--` is parsed by `engram` as a flag, producing `rc=1` with the real error on stdout. The function's error path only captures `result.stderr` (empty), so the returned `error` field is uninformative and downstream `memory_existed` is `None` with no diagnosable cause. Fix: pass `--phrase=<value>` so the value is never flag-parsed, and make the rc!=0 error path capture both stdout and stderr so a real failure is never swallowed.
- **#754** — `dev/eval/cumulative/runbook_vs_skill/phase2/fixtures/history-rewrite/steps.json` step 3's regex `git\s+(filter-branch|filter-repo)\b` only matches the space-separated subcommand form, not the equally-valid hyphenated `git-filter-repo` standalone-script invocation. Because steps 4-6 are gated `"after": 3`, a trial using the hyphenated form has steps 3-6 all scored `false` even though `done_when_checks.sh` confirms the trial genuinely did the rewrite, fetch, and force-push. Fix: broaden the pattern to `git[\s-]+(filter-branch|filter-repo)\b`.
- **#749** — `dev/eval/cumulative/matrix.py`'s `build_cfg_template(dst, warm=True)` copies the recall/learn skills from `REPO/skills/<skill>`, a path that stopped existing on 2026-07-24 (#697's `agent-instructions/` restructure). Its `if os.path.isdir(src):` guard silently skips the copy on a missing source, so any `warm=True` cfg since that date was built with no recall/learn skill present, with no error raised. Fix: correct the source path to `agent-instructions/skills/<skill>` and raise when a named skill's source is missing or has no `SKILL.md`, matching the pattern `dev/eval/traps/wrun.py::build_warm_cfg` already uses (that prior fix, under the existing `eval-warm-config-fidelity` spec, deliberately did not touch `matrix.py` — its own design.md Non-Goals excluded "retrofitting the OTHER trap harnesses' own risk of hardcoded/stale paths beyond what they inherit automatically by sharing `build_warm_cfg`"; `matrix.py` has its own independent copy of the logic, so it never inherited that fix). Also enumerate (no re-runs) which committed result files used `warm=True` after the move, to know whether any existing measurement is contaminated.
- **#750** — Two independent guards (`dev/eval/cumulative/runbook_vs_skill/probe.py::_real_vault_fingerprint`, reused by `phase2/probe_phase2.py`; and `dev/eval/isolation.py::vault_fingerprint`/`assert_vault_unchanged`, used as an end-of-run backstop by 7 other harnesses) diff the *whole* real vault before/after a run and abort if it changed at all. This false-alarms on the orchestrating session's own writes (route-evidence notes, recall-glance sidecars) that have nothing to do with trial isolation. Per Joe's decision, replace whole-vault diffing with trial-side detection: assert each trial actually ran with an isolated `ENGRAM_VAULT_PATH` (using evidence the harnesses already capture), and flag only a new real-vault note whose content names a trial directory or session id. The guard must still fail loud on a genuine leak.
- **#755** — Two distinct findings in the `bisect-before-fix` phase2 fixture: (1) `probe_phase2.py`'s `detect_question_stop` is order-insensitive — it flags `question_stop=True` for a trailing, genuinely separate follow-up question asked *after* the trial already completed and verified the task (no mutation follows it, which is all the current check looks for), identically to a trial that stopped before finishing. Fix: make it order-aware using the already-computed `end_state` result — a trial whose final state already satisfies `done_when_checks.sh` cannot have a legitimate pre-completion stop, since all its mutations necessarily happened before any ambiguity with no mutation after it. (2) Runbook 846 step 6 requires filing a separate follow-up issue for a pre-existing regression even under its narrow fix-applied exception, but the `bisect-before-fix` fixture repo has no issue tracker or filing convention, so a shim-following agent has no way to satisfy that bar and legitimately stops to ask. Fix: give the fixture a minimal local `ISSUES.md` convention named in the task prompt (runbook 846 itself is not changed).

## Capabilities

### New Capabilities
- `eval-trial-vault-leak-detection`: trial-side (not whole-vault-diff) detection of a trial reaching the operator's real vault, replacing the two existing whole-vault-fingerprint guards' false-positive-prone approach while keeping them failing loud on a genuine leak (#750).
- `eval-phase2-fixture-scoring-fidelity`: the runbook-vs-skill phase2 probe's step-detection regexes and question_stop detection accurately reflect genuine trial behavior (no false-negativing a real success), and its fixtures provide a satisfiable local target for any action a followed runbook requires (#754, #755).

### Modified Capabilities
- `eval-warm-config-fidelity`: extend the existing "warm config SHALL verify real skill sources and raise on a missing/empty source, with a path derived from the calling file's own location" requirements to explicitly cover `dev/eval/cumulative/matrix.py::build_cfg_template`, the second independent implementation of this same contract that was out of scope for the capability's original fix (#749).
- `memory-loop-audit`: extend the existence-check requirement so the audit's `engram query` invocation passes phrase/text values safely regardless of leading characters, and a failed existence check preserves the tool's actual error output instead of silently swallowing it (#787).
