## Why

Five independent defects were found in the `dev/eval` Python eval-tooling surface while running audits and probes (#787, #754, #749, #750, #755). Each one silently corrupts a measurement rather than failing loud: an audit instrument's CLI invocation drops error text and leaves "memory existed" fields empty; a scorer regex misses a valid, commonly-used invocation form and mis-scores a genuine success as a failure; a warm-config builder silently produces a skill-less config (the same bug class already fixed once, in a sibling function, by `eval-warm-config-fidelity` — but not here, since that fix was deliberately scoped to the one confirmed-broken function); a vault-leak guard false-alarms on the orchestrating session's own writes, costing an investigation for nothing; and a question-stop scorer can't tell a trailing follow-up question asked *after* a trial fully completed and verified its task from a genuine pre-completion stop. All five were found during real audit/probe runs, not hypothesized — each has a reproducible trigger, and for #750 and #755's fixture gap, Joe has already selected the fix direction from a set of options; #787/#754/#749's fixes are specified directly in their issue text. Fixing them now, in one batch, prevents each from continuing to quietly bias eval results that other work (including the future #710 Go port of this tooling) will build on.

## What Changes

- **#787 — the audit instrument's `engram query` call silently loses a real error.** `audit_moments.py::_run_engram_query_at_moment` passes `--phrase <value>` as two argv elements; a phrase starting with `--` is parsed by `engram` as a flag, failing with the real error on stdout, while the function's error path reads only `result.stderr` (empty). **Fix:** pass `--phrase=<value>` (single-argument form) so the value can never be flag-parsed, and capture stdout too so a real failure is never swallowed.
- **#754 — a scorer regex false-negatives a genuine success.** `history-rewrite/steps.json` step 3's `git\s+(filter-branch|filter-repo)\b` only matches the space-separated form, not the equally-valid hyphenated `git-filter-repo` standalone invocation; steps 4-6 are gated behind it, so a trial using the hyphenated form scores `followed_all=false` despite `done_when_checks.sh` confirming it genuinely did the rewrite. **Fix:** broaden to `(?<![\w-])git[\s-]+(filter-branch|filter-repo)\b` (a left-boundary guard is required — see design.md D4 for why the issue's own suggested pattern introduces a new false-positive class).
- **#749 — a warm-config builder silently ships a skill-less config.** `matrix.py::build_cfg_template(dst, warm=True)` copies skills from `REPO/skills/<skill>`, a path dead since the 2026-07-24 `agent-instructions/` move (#697); its `if os.path.isdir(src):` guard silently no-ops on the missing source. The identical bug was already fixed once, in the sibling function `wrun.py::build_warm_cfg`, under the existing `eval-warm-config-fidelity` spec — but that fix's own Non-Goals explicitly excluded `matrix.py` (a separate, independent implementation of the same contract). **Fix:** mirror `wrun.py`'s fix exactly (corrected path, raise on missing/empty source); also enumerate (read-only, no re-runs) which committed result files used `warm=True` after the move.
- **#750 — a whole-vault-diff guard false-alarms on the orchestrator's own writes.** `probe.py::_real_vault_fingerprint` (reused by `phase2/probe_phase2.py`) and `isolation.py::vault_fingerprint`/`assert_vault_unchanged` (an end-of-run backstop for 7 other harnesses) each diff the *whole* real vault before/after a run and abort on any change — including the orchestrating session's own legitimate writes (route-evidence notes, recall-glance sidecars), which cost a real investigation in #750's own incident. **Fix** (Joe's selected option, "Trial-side detection"): stop diffing the whole vault; detect leaks via each trial's own isolation evidence and flag only a new real-vault note whose content names a trial dir/session — still failing loud on a genuine leak. All 9 call sites (not only `probe.py`'s demonstrated one) migrate to the same mechanism — see design.md D9 for why uniformly, in this design's own reasoning, not as a Joe-attributed instruction.
- **#755 — two distinct findings in the `bisect-before-fix` phase2 fixture.** (1) `detect_question_stop` is order-insensitive: a trailing, separate follow-up question asked *after* a trial already completed and verified its task scores identically to a trial that stopped before finishing. **Fix:** thread the already-computed `end_state` into it, short-circuiting to `False` whenever `end_state` is `True`. (2) Runbook 846 step 6 requires filing a follow-up issue even under its narrow fix-applied exception, but the fixture repo has no issue tracker, so a shim-following agent has no way to comply. **Fix:** give the fixture a minimal local `ISSUES.md` convention named in the task prompt (runbook 846 itself is not changed — Joe's decision).

## Capabilities

### New Capabilities
- `eval-trial-vault-leak-detection`: trial-side (not whole-vault-diff) detection of a trial reaching the operator's real vault, replacing the two existing whole-vault-fingerprint guards' false-positive-prone approach while keeping them failing loud on a genuine leak (#750).
- `eval-phase2-fixture-scoring-fidelity`: the runbook-vs-skill phase2 probe's step-detection regexes and question_stop detection accurately reflect genuine trial behavior (no false-negativing a real success), and its fixtures provide a satisfiable local target for any action a followed runbook requires (#754, #755).

### Modified Capabilities
- `eval-warm-config-fidelity`: extend the existing "warm config SHALL verify real skill sources and raise on a missing/empty source, with a path derived from the calling file's own location" requirements to explicitly cover `dev/eval/cumulative/matrix.py::build_cfg_template`, the second independent implementation of this same contract that was out of scope for the capability's original fix (#749).
- `memory-loop-audit`: extend the existence-check requirement so the audit's `engram query` invocation passes phrase/text values safely regardless of leading characters, and a failed existence check preserves the tool's actual error output instead of silently swallowing it (#787).
