## Context

The memory-loop audit (2026-09-02 through 2026-09-06 gate review, `dev/eval/audit/REPORT-2026-09-02.md`) measured the writing side as the memory loop's dominant loss: the learn step fired for only **5.6% of worth-learning moments** (W2, 4/71, CI95 [1.4, 11.3]); **67 lessons were lost**, of which **40 (59.7%) were judged realistically reachable by a completion-report-lessons step**. The single largest bucket is **39 missed success-reinforcements** (learn's kind-4 almost never fires). The audit's read-side finding sharpens the case: failures memory "would have helped with" trace overwhelmingly to lessons never captured (9 of 11 fixable failure-family moments had nothing relevant in the vault at their timestamps) — write loss surfacing downstream as failures, not read loss.

Existing context:
- The memory loop is integrated across `route` (dispatch), `please` (orchestration), and `learn` (closing write). Each skill is already versioned in CI alongside the code and measured for behavioral change (ADR-0021).
- The vault is the source of record; the learn skill already handles writing to it via `write-memory` subagent.
- The audit data is labeled, archived, and serves as the baseline for the pre-registered re-measure (details in D-E below).
- Joe's 2026-09-06 constraints: **skill/guidance-markdown only** (no hooks — not live enough and harness-specific; no new engram code in v1 — this v1 is the deliberate test of whether the agent can behave reliably from md alone), and a **capture-then-curate** quality posture (low bar at capture time, quality control at a separate curation step, both implemented on existing surfaces).

## Goals / Non-Goals

**Goals:**
- Raise the firing rate of worth-learning moments (primary metric W2) from 5.6% toward Joe's bar by implementing three behavioral changes to the memory-loop skills.
- Implement all three changes as skill-text edits only, with no new code in v1 (deliberate design test: can the agent behave reliably from md alone?).
- Measure adherence to the new LESSONS contract (~93% output adherence, per the #655 precedent — a prior engram effort that measured adherence to a mandated completion-report output contract).
- Establish the curation step as a durable mechanism for future quality control.
- Pre-register the re-measurement before any code runs, per ADR-0028 D-G.

**Non-Goals:**
- Building hooks, a watcher, or a mechanical validator (all parked for v2, contingent on re-measure results).
- Adding storage or plumbing — use existing surfaces only (skill text, session LESSONS lines, vault notes via write-memory).
- Changing the core learn taxonomy or its existing Step-2 quality bar (the four moment kinds and the confirmed-not-hypothesized / general-principle requirements already in `agent-instructions/skills/learn/SKILL.md`).
- Modifying engram's binary or CLI.

## Decisions

- **D-A — LESSONS line contract and format:** Every dispatched subagent's completion report must end with a `LESSONS:` line. Format is either `LESSONS: none` (when no learnable lessons exist) or `LESSONS: <lesson1>` (for a single lesson) or `LESSONS: <lesson1>, <lesson2>, <lesson3>` (for up to three lessons). Each lesson is a one-line summary — confirmed corrections, surprising findings, validated approaches; deliberately low bar, these are offers not vault notes. The line is mandatory by instruction; the orchestrator re-asks once if it's missing and collects lines without judging them in-flight. Precedent: measured output-contract adherence is ~93% (#655), so this places the bar within proven reach. Why this format: one-liners are easy to scan and ingest; capping at 3 keeps the overhead low; "none" is explicit and avoids ambiguity over empty/missing.

- **D-B — Curation location and process:** The closing learn's sweep gains an explicit input — scan the session's collected `LESSONS:` lines (from all dispatched work, accumulated by the orchestrator as it runs). Judge each line against the learn skill's existing Step-2 bar (already in `agent-instructions/skills/learn/SKILL.md`): the line maps to one of the four moment kinds — kind 1 corrections, kind 2 explicit save-requests, kind 3 reversals, kind 4 confirmed approaches — AND is confirmed rather than hypothesized (kind 4 requires resolved uncertainty or explicit specific confirmation, never bare success) AND states a general reusable principle with a retrieval-shaped situation, not a session-specific narrative. Lines that clear the bar crystallize via write-memory as usual; the rest are discarded silently. The report line itself is the disposable offer tier — no new storage, no new tracking, just the lines that pass the bar get written. Why here: the closing learn is the natural join point (it already runs at the end of every session and writes to the vault); curating at write time closes the loop with zero new plumbing; silently discarding non-qualifying lines prevents vault pollution without adding a separate log.

- **D-C — Kind-4 (success-reinforcement) recalibration:** The kind-4 scan's cue gains concrete, audit-derived positive exemplars to make success moments more recognizable. Add a completion-moment scan anchor, resolved as: the kind-4 scan fires at the moment a unit of work's outcome is CONFIRMED — a review verdict lands, a check/test passes, or the user explicitly confirms — and, at the closing learn, over the session's completion reports and collected LESSONS lines (not "final output" generally: the observable signal is the confirmation event, which the RED pressure test can exercise directly). The bar itself (resolved uncertainty or explicit specific confirmation — never bare success) does not move; only its recognizability does. Why audit exemplars: the audit identified 39 missed kind-4 moments; the three exemplars chosen from those real cases are listed in `tasks.md` task 1.3 (validated-design-assumption-by-targeted-search; defect-confirmed-by-targeted-reproduction-test; vendor-claims-systematically-verified-not-assumed). Why completion-moment anchor: many learnable successes are embedded in the final confirmation; anchoring the kind-4 scan there catches them.

- **D-D — Testing and TDD discipline:** All three skill edits (`route`, `please`, `learn`) go through `superpowers:writing-skills` TDD (repo rule, enforced in CLAUDE.md). For each: RED pressure test (runs the skill's instruction set to establish baseline behavior without the new LESSONS logic), edit the skill text, GREEN behavioral test (verifies the new LESSONS logic fires as expected). No SKILL.md edit ships without this cycle. Why superpowers:writing-skills: it enforces the cycle, prevents partial edits from shipping, and the skill itself is a practiced tool in this repo (used on #655, #739 refinements).

- **D-E — Pre-registered re-measurement (commitment before running):** Before v1 ships, commit in writing to the instrument, the timeline, and the metric. Re-measure after ≥2–3 weeks of natural usage (long enough for lessons to accumulate, short enough to capture v1's impact before drift). Use the committed audit instrument (`dev/eval/audit/run_audit.py`, instrument v2 with bootstrap CIs). Primary metric is W2 (% of worth-learning moments where learn fired), secondary metrics are lost-lessons total and reachable share. Counting unit per-moment (same as the audit). Instrument version declared on both sides (baseline v2, re-measure v2) so results are comparable. Cost: ~$35 (similar to the audit's LLM spend). Go/no-go gate: if W2 moves below Joe's bar in the re-measure, escalate to code/validator/watcher (per D-F). Why pre-commit: per ADR-0028 D-G, mechanical commitment prevents p-hacking; Joe's 2026-09-01 override applies here (no pre-set thresholds, judgment call at gate time). Why per-moment: consistent with the audit's measurement unit; allows direct comparison.

- **D-F — Parked escalations, gated on re-measure:** Three directions are explicitly parked, each with the same revisit condition: post-v1 re-measure via `run_audit.py` (D-E). Escalate only if re-measure shows W2 still below Joe's bar. (1) **Watcher/metacognition layer:** v1 batch mining of the append-only chunk index → offers; v2 streaming transcript tail + watcher-salience channel in recall's payload (harness-agnostic but code). (2) **Mechanical validator on the LESSONS contract:** the guarantee layer per note 198's prose-caps finding (prose mechanisms cap below ~95% adherence). (3) **Hooks/harness push:** out for Claude Code entirely; Pi-era. Why gate on re-measure, not pre-build: Joe's constraints were "md-only test" for v1; escalations require code + harness changes, which stay parked until measured data shows they're needed. Note 198 documents the ceiling (~95%); if v1 hits that naturally, validators waste effort. If v1 undershoots, the re-measure will show it.

## Risks / Trade-offs

- [Prose mechanisms alone might not sustain >95% LESSONS adherence] → this is not a blocker for v1 (test of whether md-only works) but will trigger escalation design if the re-measure shows it (D-F). Measured precedent (#655) is ~93%, within acceptable range for a first iteration.
- [Curation step could be noisy or miss learnable lines] → learn's existing Step-2 bar is conservative and field-tested; curating at write time catches obvious non-learners; if the re-measure shows low rate, the gate can be reviewed (but don't change it mid-cycle to avoid confounding).
- [Skill edits themselves could introduce behavioral regressions] → superpowers:writing-skills TDD (D-D) catches these before deployment; each edit is red-green-refactor, not ad-hoc text changes.
- [Kind-4 exemplars might be insufficient] → 2–3 audit-derived examples set a reasonable bar for v1; if the re-measure shows kind-4 is still firing rarely, the exemplars can be refreshed or expanded (one change, no code).
- [The 2–3 week re-measure window might be too short to surface changes] → the window was calibrated to Joe's real usage cadence during the 2026-09-06 brainstorm (per his standing guidance to calibrate time windows to his actual work rhythm, not an assumed timescale); if drift emerges later, the audit instrument is repeatable (part of the long-term measurement infrastructure per ADR-0028).
