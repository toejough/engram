## Goals / Non-Goals

**Goals:** build the observe-mode instrument (mechanical extractor + semantic auditor + oracle); run the first cross-repo measurement over main + subagent transcripts; produce the labeled funnel, the #739 slice, credit-record files, the gap harvest, LEDGER rows + coverage-map index; decide the pre-registered Phase 2 gate.

**Non-Goals:** consuming credit records or writing the vault in any way; experience records (`.exp.json`); replay or mine modes; `engram audit` binary; editing delegate.md/learn.md/recall.md or any SKILL.md; firing `/learn` or `/recall` live as part of measurement (the corpus is snapshots); Phase 2 mechanisms.

## Decisions

- **D-A — Corpus:** main + subagent transcripts across all of Joe's active repos (Claude Code `~/.claude/projects/<mangled>/…` main session `.jsonl` + `<session>/subagents/**` including `subagents/workflows/**`; Pi paths verified live, scope falls back to Claude-Code-only with documented rationale if absent). Stratified single-read-sized sample; sessions ≥ 500 KB are windowed (measured limit: no single agent audits a 570 KB session exhaustively, calib-v2). Windows are single-read-sized: <=150 KB, split at turn boundaries (the 2026-06-28 sample's 8-180 KB range), boundaries recorded in the manifest. Sample size and strata documented in the corpus manifest before any LLM spend. Rationale: single-repo retention bias inverted a finding once (vault note `feedback_verify_mined_corpus_is_representative`).
- **D-B — Two-tier instrument:** the mechanical extractor runs over the **full corpus** (denominators and fire-units come from real counts, never assertions — runbook 824); the semantic auditor runs over the **stratified sample** of windows. Joined on (transcript, anchor). Semantic detection per vault note 112 (68% of failures are subtle; word-match misses two-thirds): over-match then prune, gate on false-negative rate against hand labels, false positives are cheap. The auditor runs as headless `claude -p` spawns under an isolated `CLAUDE_CONFIG_DIR` (the established dev/eval mechanism — no raw API key required); the stub in any fixture-verification step means a canned response, no network. Model tiers per the 2026-06-28 precedent: detection = haiku (calib-v2: haiku matched sonnet 5/5 at single-read size), the false-negative re-audit of low-yield windows = sonnet ("stricter" means a more capable model), judgment columns on detected moments = sonnet. Success moments are first-class (a surfaced memory visibly shaping an action) — they are the reinforcement half of ADR-0028's loop and the learn skill's kind-4 (confirmed approaches) analog.
- **D-C — Existed-at-T oracle:** the auditor derives its own phrases from the moment (not the agent's phrasing — the agent's phrases are what "keyed" is judged against, separately). Notes: query a read-only `git worktree add --detach` checkout of the vault at the last commit ≤ T → DERIVED; if the vault predates git or the moment predates history, filter by `created ≤ T` → ESTIMATE (amendments after T are invisible to this filter; label carries the caveat). Chunks: filter by `IngestedAt ≤ T` → DERIVED. Every oracle engram invocation runs under #708 isolation; worktrees are cleaned up; the live vault is never written.
- **D-D — Per-moment record schema** (the funnel, ADR-0028 D2): identity (transcript, anchor, ts, repo, harness, role main/subagent, dispatch type); moment_type ∈ {failure, correction, rework, success, dispatch}; narrative + evidence pointer; read-side columns exists (+ kind ∈ {chunk, fact, feedback, runbook, qa} + generic|idiosyncratic + oracle method), fired (glance|deep|injected|none), keyed, surfaced (+ rank, superseded-above-current flag), applied (+ deviation ∈ {none, ignored, partial, step-skip, mis-order, contradicted}); write-side columns learn_moment, learn_fired, written (+ quality: situation-keyed, supersession-used, non-duplicate), strengthened (activate on used notes; mismatch flagged); boundary columns (injected refs; for dispatch moments: orchestrator-surfaced-but-not-injected refs); klass per runbook 824. Dispatch type is mechanical, no judgment: the parent's Agent `tool_use` input `subagent_type == "fork"` -> fork; a transcript under `subagents/workflows/**` -> workflow; else fresh; a `<fork-boilerplate>` marker in the subagent's turn-1 is the cross-check.
- **D-E — Injected counts as searched-and-surfaced** (Joe's rule): for subagents, memories present in the dispatch prompt score fired=injected and surfaced=yes; forks inherit the full parent context and are injected structurally. The read-side dispatch gap is measured on the **orchestrator side** at dispatch moments (had-vs-injected), which is what replaces the prior D3 fork-exclusion arithmetic.
- **D-F — Credit-record schema (emission only):** JSONL, one record per (moment × note): `{moment_id, note_ref, situation_text, outcome ∈ {applied-helped, applied-hurt, surfaced-ignored, injected-unused, absent-needed}, ts, evidence: {transcript, anchor}}`. `absent-needed` names a note that should exist (feeds the gap harvest). No consumer in this change; the schema is the contract the credit-loop change builds against.
- **D-G — Pre-registration:** before the full run, commit (a) fire-units per axis (primary: per-moment; secondary: per-dispatch, per-transcript), (b) the Phase 2 gate thresholds — write-side: % of lost lessons reachable by completion-report harvest; read-side: % of dispatch-moment losses reachable by dispatch injection — and (c) the acceptable-outcomes list mapping observed numbers → GREEN/YELLOW/RED. Chosen before the numbers exist, per house discipline.
- **D-H — Python-first under `dev/eval/audit/`** (ADR-0028 D5): the gate #739 waits on needs the measurement, not product plumbing; dev/eval owns skill/shape evaluation under the split; promotion into `engram audit` (DI, checker-thin API, specs) lands with the credit-loop change, against this change's implementation-agnostic capability spec.
- **D-I — Outputs and recording:** per-moment JSONL + credit JSONL + the report (labeled criteria table, one narrative per major finding); LEDGER rows one-per-claim with raw-data paths; the coverage-map index (memory function × kind → evidencing rows + measured rate) added as a new LEDGER section with all existing anchors untouched; gap harvest per the note-495 two-rung ladder, quoted so the executor needs no vault access: rung 1 = "amend an existing note or write a new one — the user owns their vault, the change takes effect on their next recall"; rung 2 = "everything else — engram code, skills, ambient guidance — all ship from the repo via engram update" and is a last resort. The note-803 test decides the rung: would a note stating the fix ever be retrieved AT THE MOMENT the bug occurs, given the procedure's own query phrasing at that step? If the step's queries are about the task (not the procedure's own correctness), a note has no reliable trigger surface there and only rung 2 reaches the bug.
- **D-J — LEDGER/issue writes are user-gated:** present the measured verdicts and the gate decision to Joe before writing LEDGER rows or updating #739/#718/#742 (precedent: the #642 plan's D9 gate on durable-record mutation).

- **D-K — Execution environment:** the instrument is developed and unit-tested in the dev env against synthetic fixtures; corpus discovery (tasks 1.x) and the measurement run (tasks 5.x) execute on the HOST, where the real multi-repo `~/.claude/projects`, any Pi transcripts, and the git-controlled vault live. A dev-env sandbox (one repo's transcripts, no local vault, `ENGRAM_PARENT` remote) is NOT an acceptable measurement corpus — a single-repo sample inverted a finding once (D-A's retention-bias lesson) and the oracle has nothing to check out. Coordination follows the hermetic dev-env doctrine: instrument lands via GitHub; the host pulls and runs.

## Risks / Trade-offs

- [LLM auditor cost] → full corpus is mechanical-only; LLM spend is bounded to the stratified sample + calibration; estimate confirmed at pre-registration (~$20–50 at 2026-06-28 scale).
- [Detector bias undercounts subtle moments] → miss-rate gate + conservative labeling inherited from the precedent; the FN check (stricter model re-audits low-yield windows) is part of calibration.
- [Scorer/judge artifacts] → hand-read ≥3 transcripts against the scorer before any paid run (vault note 505: a keyword scorer fired on table headers; hand-reading is the only pre-spend calibration signal).
- [Oracle resolution coarse where vault commits are sparse] → per-moment DERIVED/ESTIMATE labeling makes it visible; no backfill (ADR-0028 D6).
- [Pi transcripts unavailable or differently shaped] → documented Claude-Code-only fallback (D-A); the capability spec is harness-agnostic.
- [Scope creep into consuming credit records] → hard out-of-scope; the emission schema is the only contract.
