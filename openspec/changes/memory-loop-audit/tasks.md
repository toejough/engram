## 3. Semantic auditor (sampled windows)

- [x] 3.1 Build the auditor's prompt and runner script (`dev/eval/audit/audit_moments.py`): split into windows per task 1.2; detect every moment type from design.md D-D (failure / correction / rework / SUCCESS / DISPATCH — successes matter just as much as failures, not an afterthought); answer the scorecard questions for each one; over-flag first and let the model itself discard non-moments; and write out one JSONL record per moment, joined to the mechanical extractor's events by transcript and location. Done when: the runner works end-to-end on one example window using a stubbed model (a canned reply, no real network call); real runs use the automated `claude -p` process at the model tiers decided in design.md D-B (haiku for detection, sonnet for re-checking low-yield windows, sonnet for answering the judgment questions).
- [x] 3.2 Add the point-in-time check inside the runner: come up with search phrases for each moment; build the as-of-that-moment set of notes (a temporary, read-only git checkout at the last commit before the moment, always cleaned up afterward) and chunks (filtered by ingestion date); run `engram query` under the existing `dev/eval/isolation.py` sandboxing (#708 — confirm isolation before every call); judge whether a relevant memory existed, what kind it was, and whether it was generic or specific to the situation; and label each record's answer DERIVED or ESTIMATE per design.md D-C. Done when: a test proves the sandboxing works (an empty scratch vault returns zero results), and a trial run is shown not to have changed the real vault at all.
- [x] 3.3 Calibrate BEFORE running the real thing: hand-label a representative sample of 10-20 windows (covering both main-agent and subagent, across at least 2 repos — this needs the real host data, see D-K; a single-repo dev sandbox can't satisfy it); measure how many real moments the detector missed compared to those hand labels; write down, in advance, the miss-rate the full run has to meet; and run the stricter re-check on any low-yield windows, following the 2026-06-28 precedent. Then hand-read at least 3 full trial outputs against the scoring and joining logic (vault note 505: this kind of check only tells you anything before the results start looking legitimate). Done when: the calibration data and the pre-agreed miss-rate tolerance are both committed before task 5 starts.
