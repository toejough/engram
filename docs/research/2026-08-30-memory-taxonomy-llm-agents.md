# Memory Systems for LLM Agents — A Survey (as of August 2026)

**Audience:** an engineer whose north star is a memory system mirroring the human episodic/semantic/procedural taxonomy, currently running a Zettelkasten-vault + embedding-retrieval + situation-keyed-runbook design (engram).

---

## 0. The taxonomy itself, and one sharp caveat before the tour

The human-psychology frame everyone borrows: **working memory** (active, capacity-limited), **episodic memory** (autobiographical events — Tulving), **semantic memory** (de-contextualized facts), **procedural memory** (skills — Squire's *nondeclarative* branch, acquired by practice, expressed through performance rather than recollection).

The caveat that matters for your design: in humans, procedural memory is *not recollected* — you don't retrieve a description of riding a bike, you just ride. A text runbook retrieved into context is therefore, psychologically, **declarative memory about a procedure** ("knowing-that about knowing-how"), not procedural memory proper. Only two things in the agent stack are procedural in the strict sense: **model weights** and **executable agent code**. CoALA makes exactly this distinction; almost every retrieval-based "procedural memory" product ignores it. This is not pedantry — it predicts the field's dominant failure mode (§8): a retrieved description must still be *read, believed, and applied*, whereas true procedural memory executes unconditionally. Every system below should be judged on where it sits on that spectrum.

2025–2026 surveys have converged on essentially your taxonomy as the organizing frame — e.g. [Memory for Autonomous LLM Agents: Mechanisms, Evaluation, and Emerging Frontiers](https://arxiv.org/html/2603.07670v1) uses retention (short/long-term) × functional form (episodic/semantic/procedural), and the [From Storage to Experience survey](https://arxiv.org/pdf/2605.06716) traces the field's shift from storage-centric to experience-centric designs. So the north star is now the field's mainstream *descriptive* frame. Whether mirroring it is a good *implementation* blueprint is a separate question (§9).

## 1. CoALA — the canonical frame (Sumers, Yao, Narasimhan, Griffiths; arXiv 2309.02427, TMLR 2024)

**What it is:** not a system — a cognitive-architecture framework (lineage: SOAR/ACT-R) that factors a language agent into memory modules (working, episodic, semantic, procedural), an action space (internal: reason/retrieve/learn; external: ground), and a decision loop.

**What CoALA says procedural memory IS:** the **LLM's weights (implicit)** plus the **agent's code (explicit)** — the decision procedures, and a **skills library** of learned code (it cites Voyager as the exemplar). Procedural *learning* — an agent writing new skills or modifying its own code — is flagged as the highest-risk, highest-reward, least-explored form of learning. Episodic = stored experiences; semantic = world/self knowledge (including facts distilled by reflection); working = the active context.

**The tension you asked about:** retrieval-based systems (Mem0, Zep, most "memory layers") implement procedural memory, when they claim it at all, as *another text partition retrieved like anything else*. Under CoALA that is a category error — retrieved text lands in working memory and merely *influences* the fixed decision procedure; it does not extend it. Skill libraries (Voyager, Claude Skills with bundled scripts) are the faithful implementation; text runbooks sit in between: declarative in storage, procedural in intended effect.

**Categories:** defines all four; implements none (it's a lens, not code).

## 2. MemGPT / Letta — the OS analogy (Packer et al., arXiv 2310.08560; Letta 2024–2026)

**Mechanism:** virtual context management. **Main context** (system instructions + editable "core memory" blocks + FIFO message queue) vs **external context**: *recall storage* (full conversation log) and *archival storage* (arbitrary documents). The agent manages its own memory via self-editing tool calls (`core_memory_append/replace`, archival insert/search), with heartbeats for multi-step management — paging, à la OS.

**Recent Letta developments:**
- **[Sleep-time compute](https://www.letta.com/blog/sleep-time-compute/)** (paper + [repo](https://github.com/letta-ai/sleep-time-compute), April 2025): a background agent uses idle time to reorganize/rewrite memory blocks — offline consolidation, the closest engineering analog to sleep-dependent episodic→semantic consolidation in humans. Also positioned as cost/latency arbitrage (pre-compute inferences before the user asks).
- **Agent File (.af):** open serialization of full agent state (memory blocks, tools, config) — portable, diffable, checkpointable agents.
- **[Letta v1 agent loop rearchitecture](https://www.letta.com/blog/letta-v1-agent/)** (2025–2026): explicit lessons from ReAct, MemGPT, and Claude Code; memory blocks + filesystem-style memory converge notably toward the CLAUDE.md/file-memory pattern (§6).

**Categories:** **working** (core blocks — the field's best-developed working-memory story), **episodic** (recall storage, raw log), **semantic** (archival + distilled facts in core blocks; sleep-time compute strengthens the episodic→semantic path). **Procedural: ignored** — the agent's procedures live in a fixed system prompt and tool set; Letta agents do not mine skills or workflows from experience. (Letta's memory-block *rewriting* edits semantic/persona content, not procedures.)

## 3. Generative Agents — memory stream + reflection (Park et al., UIST 2023)

**Mechanism:** every observation is appended to a time-stamped **memory stream** (episodic). Retrieval scores each record by **recency** (exponential decay, factor ≈0.995) + **importance** (LLM-rated 1–10 at write time) + **relevance** (embedding cosine), normalized and summed. **Reflection:** when summed importance of recent events crosses a threshold (~150), the agent asks itself what higher-level questions the recent memories answer, and writes the synthesized abstractions *back into the stream* with citation links to their evidence — episodic→semantic synthesis, recursively (reflections over reflections). Plans are generated and decomposed, also stored as memories.

**Why it still matters:** it's the origin of three now-ubiquitous ideas — scored retrieval beyond pure similarity, periodic reflection as memory *synthesis* (ancestor of Letta's sleep-time compute, A-MEM's evolution, engram's crystallization), and memory-as-append-only-stream-with-derived-layers.

**Categories:** **episodic** (the stream — the purest implementation in the field), **semantic** (reflections), working (the day's plan/context). **Procedural: ignored** — behavior is emergent from prompting; nothing executable or workflow-like is learned. Importance-at-write-time is also its weakest validated component (§8).

## 4. Skill libraries and workflow memory — procedural memory done seriously

**Voyager** (Wang et al. 2023, Minecraft): the canonical *executable* skill library. Skills are working JavaScript programs, verified in-environment, stored keyed by an embedding of their description, retrieved by task similarity, and **composed** (complex skills call simpler ones). Results: 3.3× more unique items, 2.3× longer travel, up to 15.3× faster tech-tree milestones vs prior SOTA. **Categories: procedural (executable — the CoALA-faithful kind), plus a thin episodic trace during learning. Semantic: ignored.** Caveat: results are GPT-4-in-Minecraft; the pattern transfers (it's essentially what coding agents do with helper scripts), the numbers don't.

**CLIN** (Majumder et al. 2023, AI2, ScienceWorld): continual learning via a memory of **causal abstractions** ("action X is necessary for Y"), rewritten across trials. Semantic in form, procedural in function — knowledge *about* what works, not executable. **Categories: semantic-causal + episodic raw material; procedural (declarative form only).**

**AWM — Agent Workflow Memory** ([Wang, Mao, Fried, Neubig, arXiv 2409.07429](https://arxiv.org/abs/2409.07429), ICML 2025): **the closest published analog to runbooks mined from experience.** Induces reusable **workflows** (common subroutines, as text) from the agent's own trajectories — offline from training examples or **online from its own test-time successes** — and injects selected workflows into the prompt. Results: **+24.6% relative on Mind2Web, +51.1% relative on WebArena** over baselines, *beating human-expert-written workflows by 7.9%*, with fewer steps; online AWM generalizes cross-task/website/domain, +8.9 to +14.0 absolute as train–test gaps widen. **Categories: procedural (textual workflows) mined from episodic; semantic ignored.** The beats-human-runbooks result is the single most important datapoint for your design: *mined* procedures can exceed *authored* ones.

**Memp** ([arXiv 2508.06433](https://arxiv.org/abs/2508.06433), Zhejiang/Alibaba, Aug 2025): the first paper to study agent **procedural memory as a first-class lifecycle** — Build/Retrieve/Update strategies over distilled trajectories, at two granularities (step-by-step instructions vs script-like abstractions). On TravelPlanner and ALFWorld: steadily higher success and efficiency as the memory is refined; notably, procedural memory built by a strong model **transfers to and boosts weaker models** — directly relevant to your tier-routing lever. Follow-on 2026 work continues the thread ([hierarchical procedural memory via Bayesian selection](https://arxiv.org/pdf/2512.18950), [activation-steering "neural procedural memory"](https://arxiv.org/pdf/2606.29824)).

**ReasoningBank** ([arXiv 2509.25140](https://arxiv.org/abs/2509.25140), Google, late 2025): distills generalizable **reasoning strategies from both successes and self-judged failures** (most systems only harvest successes), retrieves at test time, folds learnings back; plus memory-aware test-time scaling (more rollouts → richer contrastive signal → better memory → better rollouts). Up to +8.3% on web/SWE tasks with fewer steps. **Categories: procedural/strategic (text) from episodic.** Its harvest-failures-too stance matches your learn-skill's "capture the confirmed negative."

**Dynamic Cheatsheet** ([arXiv 2504.07952](https://arxiv.org/abs/2504.07952), Suzgun et al.): test-time-curated memory of strategies and **code snippets**; GPT-4o on Game of 24 went 10%→99% after discovering and reusing one Python solution; Claude 3.5 Sonnet's AIME accuracy more than doubled. A vivid demonstration that one *retrievable executable artifact* can dominate a benchmark.

## 5. Retrieval-architecture systems — episodic/semantic engines

**HippoRAG** (Gutiérrez et al., NeurIPS 2024) + **HippoRAG 2** ([From RAG to Memory, ICML 2025](https://arxiv.org/abs/2502.14802)): explicit hippocampal-indexing analog — open KG as hippocampal index, Personalized PageRank as pattern completion, LLM as neocortex. V2 adds passage nodes (dual-node graph), dense+sparse unification, and LLM triple filtering: +7% on associative (multi-hop) memory over the best embedding baseline while staying strong on factual/sense-making tasks — fixing v1's associativity-vs-recall trade-off. **Categories: semantic only** (corpus knowledge; "continual learning" = adding documents without retraining). No episodes-as-experiences, no procedures. The lesson for you: neuro-inspired *indexing* (graph over notes + spreading activation) is validated; it's orthogonal to what's stored.

**GraphRAG** (Microsoft, Edge et al., arXiv 2404.16130): entity KG + Leiden community detection + pre-computed community summaries, for *global sensemaking* queries over a corpus ("what are the main themes"). **Categories: semantic only; not agent memory at all** (no write path from experience) — include it only because its map-reduce-over-communities idea reappears in memory systems' consolidation layers.

**Zep / Graphiti** ([arXiv 2501.13956](https://arxiv.org/abs/2501.13956)): temporal knowledge graph for agent memory. Three subgraphs — **episodic** (raw episodes, non-lossy), **semantic entity** (extracted entities/relations), **community**. Its real contribution is the **bi-temporal model**: every edge carries event-time and ingestion-time plus validity intervals; contradicted facts are **invalidated, not deleted** — the field's only mechanically-solved staleness story (§8). Reported: DMR 94.8% vs MemGPT 93.4%; up to +18.5% on LongMemEval with ~90% latency reduction vs full-context. **Categories: episodic + semantic with temporal validity; procedural ignored.**

**Mem0** ([arXiv 2504.19413](https://arxiv.org/html/2504.19413v1)): production memory layer — LLM extraction of salient facts + ADD/UPDATE/DELETE/NOOP consolidation against existing memories, vector store, optional graph variant (Mem0g). Claims SOTA on LoCoMo at 3–4× lower token cost. **Treat the leaderboard with gloves:** Zep's rebuttal ([Is Mem0 really SOTA?](https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)) showed Mem0's comparison ran a broken Zep integration (correctly configured, Zep scored 75.14% on LoCoMo, ~10% relative above Mem0g), and there are [counter-corrections in the other direction](https://github.com/getzep/zep-papers/issues/5) (re-evaluating Zep's own 84% claim down to ~58%). The honest reading: **LoCoMo-class benchmarks cannot currently separate these systems** (§7). **Categories: episodic→semantic fact extraction (personalization); procedural ignored.** Mem0's update-ops pipeline is nonetheless the reference design for write-time conflict resolution.

**A-MEM** ([arXiv 2502.12110](https://arxiv.org/abs/2502.12110), **NeurIPS 2025**): **the Zettelkasten made agentic** — your closest academic sibling. Each memory becomes an atomic note with LLM-generated context, keywords, tags; the system proposes **links** to related notes; and — its distinctive move — **memory evolution**: integrating a new note can trigger rewrites of *existing* notes' contextual attributes, so the network's understanding keeps refining. Beats SOTA memory baselines across six foundation models on LoCoMo-style long-conversation QA. **Categories: episodic (notes from dialogue) + semantic (links, evolved abstractions); procedural ignored.** Two deltas vs engram: A-MEM's evolution is automatic-LLM-driven (rot risk, unaudited rewrites) where engram's curation is judged; and A-MEM was validated on conversational QA, not on whether a coding agent *does the task better*.

**MemOS** ([arXiv 2505.22101](https://arxiv.org/abs/2505.22101) / [2507.03724](https://arxiv.org/abs/2507.03724); [MemTensor repo](https://github.com/MemTensor/MemOS)): "memory as a first-class OS resource." The **MemCube** abstraction unifies three *substrates* — **parametric** (weights/LoRA), **activation** (KV-cache), **plaintext** — with provenance, versioning, scheduling, migration, fusion. Note the taxonomy is **systems-oriented (where memory lives), orthogonal to yours (what memory is for)**; a MemCube could hold episodic, semantic, or procedural content. Claims large LoCoMo/temporal-reasoning gains and ~35% token savings via KV reuse. Ambitious, open-source, and — fairly assessed — architecture running ahead of independent validation (§9).

**Reflexion** (Shinn et al., NeurIPS 2023): verbal reinforcement — after a failed attempt, the agent writes a natural-language self-reflection ("I failed because X; next time do Y") into an episodic buffer that conditions the next attempt. HumanEval 91% pass@1 with GPT-4; +22% AlfWorld, +20% HotPotQA. **Categories: episodic→procedural distillation, but ephemeral** — the buffer lives within a task/episode loop, not across sessions. Reflexion is the *mechanism* every learn-from-failure system (ReasoningBank, your `/learn`-at-correction) industrialized; it proved the signal exists but built no store.

## 6. The instruction layer — static procedural memory, and systems that learn it

**The static ecosystem (2024–2026):** [CLAUDE.md](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models) / AGENTS.md (open standard, adopted across OpenAI/Google/Cursor tooling mid-2025), Cursor rules (`.cursor/rules` with `alwaysApply` vs glob-triggered auto-attach), and **[Claude Skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)** (Oct 2025): a SKILL.md per capability with YAML name+description, optional `references/` and executable `scripts/`, loaded by **progressive disclosure** — index (names+descriptions) always in context; body loaded when judged relevant; references/scripts only on use. This *is* procedural memory in CoALA's sense wherever scripts are bundled (executable), and declarative-procedural where it's prose. Under your taxonomy: **procedural (static, human-authored); episodic/semantic ignored** — the layer has no write path from experience *by default*.

Also in this family: **[Anthropic's memory tool + context editing](https://www.anthropic.com/news/context-management)** (late 2025): a client-side file directory Claude reads/writes across sessions, paired with automatic clearing of old tool results (with a warning that prompts Claude to save important state to files first). In a 100-turn agentic search eval, context editing alone cut token use 84% and let workflows finish that otherwise died of context exhaustion. Claude Code's auto-memory (MEMORY.md + topic files) is the same pattern. This is **working-memory management + free-form episodic/semantic file store; procedural only insofar as the agent chooses to write itself instructions.**

**Learning/updating the instruction layer — the live frontier:**
- **Prompt optimization as procedural learning:** [GEPA](https://arxiv.org/pdf/2507.19457) (reflective prompt evolution: run tasks, LLM reads execution traces, diagnoses failures, proposes instruction edits; Pareto-frontier candidate pool) outperforms the GRPO RL baseline by 10–20% with up to 35× fewer rollouts, and beats DSPy's MIPROv2. Applied to CLAUDE.md-style files it works: [Arize's prompt-learning loop on CLAUDE.md](https://arize.com/blog/claude-md-best-practices-learned-from-optimizing-claude-code-with-prompt-learning/) and GEPA-community reports of Haiku 79%→98% on repository tasks by evolving the instruction file against a test suite. **The catch:** it requires a scoreable objective (a test suite), and long optimization erodes the *why* — files become accumulations of rules without coherent rationale ([practitioner critique](https://jedi.be/blog/2026/self-tuning-context/)).
- **ACE / evolving playbooks** (Agentic Context Engineering, late 2025): incremental delta updates to a growing playbook instead of monolithic rewrites, explicitly to avoid **context collapse** (an LLM rewriting its own instructions wholesale compresses away hard-won specifics).
- **LangMem** (LangChain, 2025) ships exactly your taxonomy as an SDK — semantic/episodic/**procedural** memory types, where procedural = the agent updating its own system prompt from feedback. **MIRIX** (arXiv 2507.07957) similarly ships a six-type taxonomy (core/episodic/semantic/procedural/resource/vault) with a multi-agent router. Both are taxonomy-mirroring *products*; neither has AWM-grade evidence that the procedural slice, specifically, drives their wins.
- Academic wrappers are appearing around the practice: [self-tuning context studies](https://jedi.be/blog/2026/self-tuning-context/), [skill-mining from open agentic repos](https://arxiv.org/pdf/2603.11808), [SkillJuror — measuring how skill organization changes runtime behavior](https://arxiv.org/pdf/2606.11543).

## 7. Evaluation evidence — what's actually known

**Procedural/workflow memory helps — this is the best-replicated positive result in the field.** Independent, methodologically distinct confirmations: Voyager (executable skills; 3.3×/15.3×), AWM (**+51.1% relative WebArena, beats human-written workflows**), Memp (TravelPlanner/ALFWorld gains + strong→weak transfer), ReasoningBank (+8.3% and fewer steps), Dynamic Cheatsheet (10%→99% Game of 24), Reflexion (91% HumanEval). Crucially these are **task-success** metrics, not QA-recall proxies — the deciding metric, in your vocabulary.

**Conversational/personalization memory benchmarks are in a credibility crisis.** The stack: **LoCoMo** (1,540 Qs; single/multi-hop, temporal, open-domain), **[LongMemEval](https://mem0.ai/blog/ai-memory-benchmarks-in-2026)** (500 Qs; adds knowledge-updates, temporal reasoning, abstention; commercial assistants drop 30%+ over sustained interaction), **BEAM** (1M–10M-token scales), **MemBench** (factual vs *reflective* memory; effectiveness/efficiency/**capacity** — degradation as the store grows), **MemoryAgentBench** (accurate retrieval, test-time learning, long-range understanding, selective forgetting), **[Mem2ActBench](https://arxiv.org/pdf/2601.19935)** (memory *utilization in action* — the retrieved-but-applied gap made a benchmark), **StreamMemBench** (streaming/future-oriented). Against all of this: the Mem0-vs-Zep wars (§5) showed vendor numbers don't survive correct competitor configuration, and the 2026 empirical audit [Anatomy of Agentic Memory](https://arxiv.org/abs/2602.19320) found benchmarks underscaled, metrics misaligned with semantic utility, **accuracy strongly backbone-dependent**, and maintenance latency/cost systematically unreported; [MemDelta](https://arxiv.org/pdf/2606.29914) adds hidden confounds and missing controlled baselines. Aggressive retrieval + a frontier model can move these benchmarks without the memory system improving at all.

**Methodological convergence with your practice:** the field's audit papers are arriving at what your evals already do — validity gates on treatment delivery, contrast-matched noise floors, degenerate-run detection, and "retrieved+applied" as the deciding metric. Your headless RED/GREEN protocol (fresh `claude -p` processes, instruction file as the only variable, fictional domains) is *stronger* than the published norm for guidance-layer evaluation, where subagent-contamination confounds go mostly unremarked.

## 8. Known failure modes — and who has solved what

**(a) Retrieval fires but is not applied.** Now formally recognized: "retrieved-but-unused" appears as a named failure class; as retrieval improves, failures **shift to post-retrieval reasoning**; *faithfulness* (did the agent use the memory) is measured separately from retrieval success ([survey](https://arxiv.org/html/2603.07670v1), [Mem2ActBench](https://arxiv.org/pdf/2601.19935)). No system has solved it architecturally — it is exactly the declarative-vs-procedural gap from §0. Mitigations in the wild: injecting memory *as instructions at the decision point* rather than as reference material (AWM puts workflows in the prompt at task start), and executable skills that bypass "apply" entirely (Voyager — the script runs). Your own application-gap framing (recall-firing guidance at decision moments) is ahead of most published work here.

**(b) Memory bloat/rot.** Empirically devastating: in one 2025–2026 medical-reasoning study, an add-all agent accumulated 2,400+ records and fell to 13% accuracy while a curated 248-record store hit 39% ([summary](https://tianpan.co/blog/2026-04-12-the-forgetting-problem-when-agent-memory-becomes-a-liability)); MemBench's *capacity* axis measures exactly this degradation. Mitigations: write-time consolidation ops (Mem0's ADD/UPDATE/DELETE/NOOP), forgetting curves (MemoryBank's Ebbinghaus decay; your confidence decay), offline consolidation (Letta sleep-time), A-MEM's evolution, and judged curation (engram's offer/curate flow — rarer in the field than it should be). ReasoningBank-style self-judged writes carry a rot risk the [faithful-self-evolution critique](https://arxiv.org/pdf/2601.22436) documents.

**(c) Stale procedures.** The least-solved for procedural content. Zep's **bi-temporal edge invalidation** is the only mechanical staleness solution shipped — and it covers *facts*, not runbooks. Nothing published invalidates a workflow when the tool/UI/API it encodes changes; Memp's Update strategies are the first systematic study. Practitioner mitigations: TTL policies, verify-on-recall, version-stamping (your sidecar model_id stamping is the same instinct applied to embeddings).

**(d) Conflicting memories.** Handled at write time (Mem0 update ops, A-MEM evolution, Zep invalidation) or punted to the reader (most systems inject both and hope). LongMemEval's knowledge-update questions measure it; scores there remain the weakest category across systems.

**(e) The firing/triggering problem — when does the agent consult memory at all?** The clearest mechanical spectrum in the field:
1. **Always-on injection** — CLAUDE.md/AGENTS.md, Cursor `alwaysApply`, ChatGPT's memory (distilled facts injected into every system prompt). *Mechanically solved firing*; pays a permanent token tax and caps content volume.
2. **Event/pattern-triggered injection** — Cursor glob rules (fire on file match), Claude Code hooks (UserPromptSubmit/PreToolUse can inject recall output). Mechanical, cheap, situation-keyed — the most underexploited point in the space.
3. **Index-always-on, body-on-demand** — Claude Skills' progressive disclosure. Firing is still a model judgment, but against a permanently visible index; a middle ground that mostly works in practice.
4. **Model-initiated tool recall** — MemGPT functions, Anthropic memory tool, engram `/recall`. Maximum capacity and freshness; *known chronic under-firing* — the model must decide to look, and doesn't. Your `--lazy-chunks` result (0/13 agents fetched sparingly/unprompted) is convergent evidence.
5. **Offline/scheduled** — sleep-time compute. Sidesteps in-loop firing for *consolidation*, but retrieval still needs one of 1–4.

Your own measurements are among the only quantified firing-cost data anywhere: recall-per-tool-call ≈147× over-fire (fatal), per-turn ≈380×, task-init ≈7×, with ~28% of failures behind the capture ceiling regardless — plus the demonstration that **always-on ambient guidance (mode 1) mechanically fixes specific under-firing cases** (headless RED 0/5 → GREEN 4/5). The field has no published equivalent of this analysis.

## 9. Verdict: proven, fashionable-but-unvalidated, and where your design sits

### Proven (multiple independent replications, task-level metrics)
- **Mining procedural memory from experience** (AWM, Memp, ReasoningBank, Voyager, Dynamic Cheatsheet, Reflexion) — the strongest-evidence corner of the entire design space, including *mined-beats-human-authored* (AWM +7.9%) and *strong→weak transfer* (Memp).
- **Executable skills > prose descriptions** where the environment permits (Voyager; Skills' bundled scripts) — sidesteps the apply gap.
- **Working-memory management**: context editing + file offload (84% token cut, completes otherwise-impossible workflows); MemGPT-style paging.
- **Progressive disclosure** for scaling instruction volume without context cost.
- **Temporal invalidation for factual staleness** (Zep's bi-temporal model — engineering-proven).
- **Curation over accumulation** (add-all 13% vs curated 39%; MemBench capacity axis).
- **Always-on/hook-based injection mechanically solves firing** for small, high-value content — at a token tax that bounds volume.
- And from your own adversarially-verified ledger, one the literature under-states: **memory pays off on idiosyncratic content** (project traps, local conventions, past decisions) and is **washed out or net-negative where the model already has priors** — which quietly explains much of the benchmark-confound mess in §7.

### Fashionable but unvalidated
- **Graph-structured agent memory as a category win** — plausible, but the Mem0/Zep wars plus judge-sensitivity audits mean no current leaderboard cleanly attributes lift to the graph itself.
- **Memory-OS abstractions** (MemCube; MemOS's parametric/activation/plaintext unification) — architecture ahead of independent evidence.
- **Sleep-time compute** — one strong first-party paper; thin third-party replication so far.
- **Automatic self-evolution of memory/instructions without regression gates** — A-MEM's unaudited evolution, GEPA without a test suite, self-rewriting context files: context collapse and rationale erosion are now documented failure modes.
- **LLM-scored importance at write time** (Generative Agents lineage) — everywhere, never separately validated.
- **Taxonomy-mirroring as an implementation blueprint** (LangMem, MIRIX): naming your modules episodic/semantic/procedural is now common; there is **no published ablation showing the taxonomy split itself** (vs. one well-curated store with good retrieval) causes wins. The taxonomy earns its keep as a *coverage checklist* — the procedural slice it forces you to build is the one with proven payoff — not as an architecture.
- **LoCoMo/LongMemEval scores as system quality** — measure retrieval-for-QA, not applied-in-action; gameable by retrieval aggression and backbone choice.

### Where the Zettelkasten-vault + embedding-retrieval + situation-keyed-runbook design sits
- **Vault:** directly validated in kind by A-MEM (NeurIPS 2025) — Zettelkasten-structured agentic memory beats flat baselines — but on conversational QA; engram's judged curation (vs A-MEM's automatic evolution) is the safer variant given the rot evidence. Your notes/links/evolution loop is mainstream-validated form.
- **Embedding retrieval:** commodity and sufficient — your own probe (MiniLM fine; note-vs-chunk *ranking* was the lever; matched-note floor 0.22→0.83 recall@5) mirrors the field's finding that retrieval policy, not encoder quality, is where systems differ. HippoRAG-2-style graph-aware re-ranking over your existing wikilink graph is the one proven upgrade path you haven't spent.
- **Situation-keyed runbooks:** you are standing in the *proven* corner — this is AWM-online/Memp territory, the best-evidenced pattern in the field — with one caveat: published wins mine runbooks *from trajectories at scale*; your correction-moment `/learn` capture is a sharper, lower-volume signal (closer to ReasoningBank's failure-harvesting) whose task-level payoff you've partially measured (C3–C6 traps) but the field hasn't benchmarked.
- **Your exposure, in field terms:** (1) the **firing problem** — engram's modes are 3/4 (guidance-nudged tool recall); the proven mechanical fix is mode 2 (hooks at task-init, where your own data says ~7× over-fire is tolerable) for a small always-on index, keeping the vault behind on-demand fetch; (2) the **apply gap** — decision-point injection of the matched runbook (AWM-style, in the prompt at task start) beats reference-style surfacing; (3) **runbook staleness** — nobody has solved it; a Zep-style validity interval on runbooks (invalidate-on-contradiction at `/learn` time) would be genuinely novel.
- **Where you're ahead of the field:** evaluation honesty (headless RED/GREEN, delivery-not-wording metrics, treatment-delivery gates, noise-floor discipline) exceeds the published norm; quantified firing-cost analysis has no published peer; the human-taxonomy north star is fully mainstream as a frame — your system already implements episodic (transcripts/chunks), semantic (notes), and procedural-declarative (runbooks/skills) slices, and the field's evidence says the procedural slice plus curation discipline is exactly where the value is.
