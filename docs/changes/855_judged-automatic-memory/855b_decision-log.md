## 855b11 A note or a passage applies when the recall skill draws on it

What arrives is what the [recall skill](../../GLOSSARY.md#recall-skill), run for the moment at its depth on the same [vault](../../GLOSSARY.md#vault), draws on: the [notes](../../GLOSSARY.md#permanent-note) it judges covered or near, the newer of two that conflict, and the passages of earlier conversations that are its evidence. ## 855b12 The moment judgement chooses the depth

The cheap-tier moment judgement answers none, glance or deep. At glance the automatic channel runs the read side of the [recall skill](../../GLOSSARY.md#recall-skill) and writes nothing but the marking of used [notes](../../GLOSSARY.md#permanent-note) and the pending copy of a used parent note; at deep it follows the skill's deep-mode semantics, write side included: crystallize an absent lesson, resolve by recency, activate ([855a2a Delivery writes what its depth writes](./855a_product-spec.md#855a2a-delivery-writes-what-its-depth-writes)). A note written at deep is marked as written automatically. Rejected: the read side only, which this change started with. Decided by: Owner (2026-10-18): "follow the deep mode semantics when deep mode is called for - make that part of the haiku decision - none/glance/deep".

## 855b14 A slow step is waited for, a stalled one is not

With no time bound before a [prompt](../793_automatic-memory/793a_product-spec.md#793a1a-terms) reaches the [agent](../793_automatic-memory/793a_product-spec.md#793a1a-terms), a step that is only slow is waited for ([855a3c 793a2d Never in the way](./855a_product-spec.md#855a3c-modified-793a2d-never-in-the-way)). A step that never answers cannot hold the prompt forever, and the host puts no ceiling on it: its type definitions (`claude-code.d.ts`, bundled with Claude Code 2.1.301 under `/private/tmp/claude-501/bundled-skills/2.1.301/e2ebd773aa00aeae2764ffb5641f2a63/plugin-authoring/types/`) give a hook a budget of `10_000` milliseconds (line 5250) but say "Each bounds the hook's OWN time: the clock stops while a `next(e)` call or any `$` call of the hook's is in flight" (line 5234), `timeoutMs` of a model call has "default none" (line 6365), and a command runs 30 seconds by default, ten minutes at most (line 3592). So the bound is a liveness bound of 2 minutes, far above any normal judgement: a judgement or delivery with no answer by then is stepped aside, delivers nothing and is shown as a failure. It is a liveness bound and not a latency target. Rejected: holding until the user interrupts; a host ceiling, which does not exist for these calls. Decided by: Owner (2026-10-18), option (b) of [855c1 How long may a judgement or delivery run before it is given up?](./855c_open-questions.md#855c1-how-long-may-a-judgement-or-delivery-run-before-it-is-given-up).

## 855b17 Supersession is the learn skill's

## 855b23 Recall runs at the points the host offers

The owner wants recall to fire as often as possible. The type definitions the owner's check named (`claude-code.d.ts`, as in [855b14 A slow step is waited for, a stalled one is not](#855b14-a-slow-step-is-waited-for-a-stalled-one-is-not)) show a mod can add context within a [turn](../793_automatic-memory/793a_product-spec.md#793a1a-terms), not only at a [prompt](../793_automatic-memory/793a_product-spec.md#793a1a-terms): a `PreToolUse` answer carries `additionalContext` ("Extra context handed to the model with the call", line 8157); a `PostToolUseFailure` answer carries `additionalContext` (line 1402) and an errored tool call's `context` is "as on an answered result" (line 13423), the text "the model reads after the tool's result and the user never sees" (line 13372); a `Stop` answer carries `additionalContext` (line 1404) and `block` is "the event's block, veto or re-prompt" (line 1314). `turn.step` cannot add context: its answer is the response, and "a hook's own value changes what the hooks above it read, never what the engine streamed" (line 14170). So three cues of the recall guidance are promised, one scenario each, at the call before a new approach is built, after the failure, and when the work is about to be declared done ([855a2e Recall moments within a turn](./855a_product-spec.md#855a2e-recall-moments-within-a-turn)); the fourth, before endorsing an approach in conversation, has no event at which context can be added and is not promised. How each event reaches the model is verified before a step relies on it ([855b21 The mod API is verified before a step relies on it](#855b21-the-mod-api-is-verified-before-a-step-relies-on-it)). Rejected: prompts only, which leaves the cues the guidance names to the [agent](../793_automatic-memory/793a_product-spec.md#793a1a-terms). Decided by: Owner (2026-10-18): "fire as often as possible - if mid-turn is possible (I think it is, per step?), then it's worth trying".
