## Summary

- No code problems found; no issues filed.
- Doc fixes: 792a2a and 792b2c1 (`engram update` has no `--vault` flag), 792a2h and 792b5c4 (an existing vault is also stamped on its first exchange-state write and by `--regenerate`), 792a2q (offers are still queued while the parent is the vault itself, deliberately).
- Everything else matched. Items that #795 and #796 change (792a2d, 792a2e, 792a2g and their scenarios) match the code as it stands today.
- Stale text outside the specs, already logged in [792d46 First-use creation does not create `Permanent/`](../792d_decision-log.md#792d46-first-use-creation-does-not-create-permanent): the `initializeVault` doc comment and the root `README.md` "Vault location" paragraph. #795 rewrites `initializeVault`; not filed separately.
- Unclear: none.
