# 792g22 curate - Adoption Audit

Audit of [792a22 curate](../792a_product-spec.md#792a22-added-curate) and the [792b](../792b_technical-spec.md) requirements whose `Supports:` lines or mapping rows cite its scenarios. Method: read `agent-instructions/skills/curate/SKILL.md` (it has no `references/`), `internal/cli/offer.go`, `amend_fold.go`, `offer_classify.go`, `serve.go` and `skillreg_accept.go`, then ran the scenarios on a binary built from this tree (`go build -o /tmp/cur22/engram ./cmd/engram`) against temp vaults with crafted pending offers (served-style with `xid` and `offer.origin`, pulled-style with `parent.links`, CRLF, skill runbook), with HOME and XDG pointed at temp dirs, `engram serve` on a loopback port for the served routes. `engram update` clones the repo from the network and was not run; its notice is verified by code and unit test. Pull-down declines need a parent and were verified by code and unit tests.

## Summary

82 rows (61 in [792a22 curate](../792a_product-spec.md#792a22-added-curate), 21 in 792b): 2 `code bug #823`, 4 `doc fixed`, 76 `match`.

- Doc problems fixed: [792a22b A note becomes pending only by an exchange](../792a_product-spec.md#792a22b-a-note-becomes-pending-only-by-an-exchange) (skill registration also writes the marker), [792b12c8 The pending marker is not set by a local learn](../792b_technical-spec.md#792b12c8-the-pending-marker-is-not-set-by-a-local-learn) (same), [792b14c14 Settling a pending offer](../792b_technical-spec.md#792b14c14-settling-a-pending-offer) (`--pending=false` is not a working flag), and the root `README.md` description of `curate`.
- Code bugs: #823 (new): the curate skill's Step 1 `grep -l '^pending: true$'` misses pending offers the binary recognizes (CRLF, trailing comment). It needs the writing-skills cycle. #797 (existing) is the cause of the stale `--pending=false` wording and is referenced, not refiled.
- Not applicable: #795 (explicit `engram init`) and #796 (README as an engram-controlled artifact) do not touch any curate requirement; the temp vaults here were created by `learn` and are unaffected.
- Known gap, not in the spec: #784, the skill does not say what to do when the content amend of a near outcome fails after the fold deleted the offer (logged in [792d124 curate scope, the scenarios only the skill text verifies, and where the sources differ from the skill and the code](../792d_decision-log.md#792d124-curate-scope-the-scenarios-only-the-skill-text-verifies-and-where-the-sources-differ-from-the-skill-and-the-code)).
- Go doc comment fixed: the `Discard` field comment in internal/cli/amend.go called `--discard` the "covered" outcome only; it now describes the bare (rejected) and `--into` (covered, near) uses.
- Title left as is: [792a22b A note becomes pending only by an exchange](../792a_product-spec.md#792a22b-a-note-becomes-pending-only-by-an-exchange) keeps its title because the anchor is linked from other capabilities that this audit may not edit.
