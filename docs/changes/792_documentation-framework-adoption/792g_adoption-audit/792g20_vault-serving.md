# 792g20 vault-serving - Adoption Audit

Audit of [792a20 vault-serving](../792a_product-spec.md#792a20-added-vault-serving) and the [792b35 vault-http-server](../792b_technical-spec.md#792b35-added-vault-http-server) requirements, plus the other [792b](../792b_technical-spec.md) requirements whose `Supports:` lines cite its scenarios. Method: read `cmd/engram/serve.go`, `internal/cli/serve.go`, `serve_learn.go`, `serve_exchange_read.go` and the served-activate code in `activate.go`; recovered the legacy `vault-serve-api` spec (`git show 964e6b02^:openspec/specs/vault-serve-api/spec.md`) and the archived `serve-vault-api` design (`git show 983ed15b^:openspec/changes/archive/2026-08-22-serve-vault-api/design.md`); then built `./cmd/engram` and ran `engram serve --addr 127.0.0.1:<port>` against temp vaults with HOME, XDG_DATA_HOME, XDG_CONFIG_HOME and ENGRAM_VAULT_PATH pointed at temp dirs, probing every route with curl (valid, malformed, oversized, wrong method, unrouted, unreadable-note, unwritable-sidecar, corrupt vault ID file, location mismatch and a local-versus-served write race).

Result: the port tracks the code closely (both were written from the same late-September code, with the Cloudflare-era and `amend`/`query-chunks` routes already dropped). One doc problem was found and fixed: the [792a20a The served command set is fixed](../792a_product-spec.md#792a20a-the-served-command-set-is-fixed) rationale still carried two stale statements from the 2026-08-22 design (a server-governed `user:` and four GET read-only commands), and a Go doc comment still named the dropped `Cf-Access-Authenticated-User-Email` header. No code problems were found, so no issues were filed. Nothing here is covered by #795 (vault init) or #796 (controlled README).
