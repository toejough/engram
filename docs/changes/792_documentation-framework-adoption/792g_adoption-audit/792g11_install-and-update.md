# 792g11 install-and-update - Adoption Audit

Audit of [792a11 install-and-update](../792a_product-spec.md#792a11-added-install-and-update) and the [792b](../792b_technical-spec.md) requirements whose `Supports:` lines cite its scenarios: [792b28 self-installer](../792b_technical-spec.md#792b28-added-self-installer) (all of [792b28c1 Install location](../792b_technical-spec.md#792b28c1-install-location) to [792b28c16 The registration step](../792b_technical-spec.md#792b28c16-the-registration-step)), [792b29 harness-deploy-sync](../792b_technical-spec.md#792b29-added-harness-deploy-sync) (all of [792b29c1 Harness detection](../792b_technical-spec.md#792b29c1-harness-detection) to [792b29c18 Guidance activation hints](../792b_technical-spec.md#792b29c18-guidance-activation-hints)), [792b18c15 Reporting a prune backlog](../792b_technical-spec.md#792b18c15-reporting-a-prune-backlog) and [792b4c4 Run with the caller's streams](../792b_technical-spec.md#792b4c4-run-with-the-callers-streams).

Method: read `internal/update/update.go` and `internal/cli/update.go`, then ran every scenario that can run on a binary built from this tree (`go build -o /tmp/a11/bin/engram ./cmd/engram`) with HOME, XDG_*, TMPDIR, GOBIN and `ENGRAM_VAULT_PATH` pointed at temp directories and `PATH` leading with a `go` shim (`go install` copies a binary or a wrapper into GOBIN; `go version -m` can answer a chosen `vcs.revision`; everything else is the real go). The sync phase ran with `ENGRAM_UPDATE_REEXEC=1` against a fixture checkout whose go.mod names the engram module; the install, downgrade and hand-off paths ran through the shim; the remote route ran with git `url.insteadOf` redirecting the clone URL to a fixture repository. Legacy sources were recovered with `git show 046c323b^:openspec/specs/update-deploy-sync/spec.md`, `git show b0916e15^:openspec/specs/update-self-reexec/spec.md` and `git show 983ed15b^:openspec/changes/archive/2026-07-28-update-reexec-fresh-binary/design.md`.

## Summary

117 rows: match 106, doc fixed 3, code bug 7 (4 earlier, then #831 for 792b28c1, 792a11a1f and 792a11a1g), covered by #795/#796 1, unclear 0.

- Code bugs: [#818](https://github.com/toejough/engram/issues/818) (`tildify` rewrites a sibling of the home directory as `~x/…`), [#819](https://github.com/toejough/engram/issues/819) (a failed re-exec fallback prints the install header twice), [#820](https://github.com/toejough/engram/issues/820) (the handed-off run re-resolves its source, so remote mode clones twice). [#812](https://github.com/toejough/engram/issues/812) (stale `--with-guidance` help and nudge) is an existing issue and is only referenced.
- Doc fixes: [792a11d The report names the source and the install](../792a_product-spec.md#792a11d-the-report-names-the-source-and-the-install) (offer-line placement), [792a11f1a A dry run on a never-synced harness leaves no trace](../792a_product-spec.md#792a11f1-uat-scenarios) (a dry run prints no planned link lines), [792a11j Only what engram owns is deleted](../792a_product-spec.md#792a11j-only-what-engram-owns-is-deleted) (adoption is the one deletion of a real entry), [792b29c11 Unmanaged entries](../792b_technical-spec.md#792b29c11-unmanaged-entries) (unmanaged entries sort per directory); README install steps (git and git-lfs are required, step 1 is a bootstrap, step 2 deploys with links), GLOSSARY `engram update` entry (clone source, canonical guidance paths) and three Go comments in `internal/update/update.go` (`BinaryVersion` and `SourceInfo.Root`).
- Covered by #795/#796: a dry run (and any update) with no vault creates one today; [795a6 Update without a vault skips the vault steps](../../795_vault-init-command/795a_product-spec.md#795a6-added-update-without-a-vault-skips-the-vault-steps) makes update skip the vault steps and never create a vault.
- Code bug [#831](https://github.com/toejough/engram/issues/831): [792b28c1 Install location](../792b_technical-spec.md#792b28c1-install-location) (the install location is read from the environment only; `go install` also honours `go env -w` and multi-entry GOPATH). It was `unclear`; Joe ruled it a bug (2026-10-10).
- Not run: the real GitHub clone and a real `go install` (the checkout's model is not a usable build here), the duplicates notice (needs a chunk manifest with duplicate groups), interactive registration prompts, manifest mode (no harness uses it), the broken-pipe hand-off abort.
