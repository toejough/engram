## Summary

Every 792a4 requirement and scenario matches the code. One doc fix: [792a4f Amend argument validation](../792a_product-spec.md#792a4f-amend-argument-validation) and its scenario [792a4f1a An invalid amend argument is refused before any write](../792a_product-spec.md#792a4f1-uat-scenarios) quoted paraphrased error texts and missed the non-empty-claim check, which the code enforces (`--supersedes "a|updates|"` fails `claim must be non-empty`); the text and table now follow the code.

One code problem outside the specified behavior: issue #797 (leaked `--pending`, `--repo` and `--user` flags on `engram amend`; see [792d70 amend --repo, --user and --pending are not specified](../792d_decision-log.md#792d70-amend---repo---user-and---pending-are-not-specified)).

Nothing here is covered by #795 or #796 (vault creation and README); note-revision never creates a vault. The `last_used` loss on a sidecar rebuild ([792d71 Rebuilding a sidecar drops its last-used date](../792d_decision-log.md#792d71-rebuilding-a-sidecar-drops-its-last-used-date)) is deliberately unspecified and was not re-tested.

Two scenarios ([792a4h1d Empty user detection keeps the prior user](../792a_product-spec.md#792a4h1-uat-scenarios) and [792a4h1e Empty user detection never writes an empty user](../792a_product-spec.md#792a4h1-uat-scenarios)) were confirmed by unit tests only, since the binary cannot make user detection resolve empty.

Verdict counts (rows above): match 81, doc fixed 2, code bug #797 1.
