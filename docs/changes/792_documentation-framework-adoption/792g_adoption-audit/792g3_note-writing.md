# 792g3 note-writing - Adoption Audit

Capability [792a3 Added: note-writing](../792a_product-spec.md#792a3-added-note-writing) and the 792b requirements whose `Supports:` lines cite its scenarios. Method: read the code, ran a binary built from this branch (`go build ./cmd/engram`) against temporary vaults with HOME, XDG and `ENGRAM_VAULT_PATH` redirected, and compared the git history of the ported text with the code.

## Summary

Counts: code bug #798 2, covered by #795/#796 1, doc fixed 1, match 109.

- All 792a3 requirements and scenarios were exercised against a binary built from this branch; behavior matches the text except one wording problem.
- doc fixed: [792a3j Luhmann placement](../792a_product-spec.md#792a3j-luhmann-placement) said "next unused" where the allocator takes one above the highest existing ID and never refills gaps. Reworded.
- code bug #798 ([learn qa: question and answer notes get two blank lines after the frontmatter](https://github.com/toejough/engram/issues/798)): QA notes have two blank lines after the frontmatter, against [792b6c2 Frontmatter block](../792b_technical-spec.md#792b6c2-frontmatter-block) and [792b6c5 Question-and-answer documents](../792b_technical-spec.md#792b6c5-question-and-answer-documents). Cosmetic; readers are unaffected.
- covered by #795/#796: the starter-README clause of [792b3c4 Vault Markdown listing](../792b_technical-spec.md#792b3c4-vault-markdown-listing).
- Not checked on the binary: the embedding-failure warning (792a3n1b) and the no-user case (792a3p1c), which could not be forced on this host; both are covered by unit tests and code reading.
- Embedding, sidecar, lock and vocabulary-engine requirements (792b8, 792b9, 792b10, 792b20) were audited only for their learn-visible behavior; their own capabilities audit the rest.
