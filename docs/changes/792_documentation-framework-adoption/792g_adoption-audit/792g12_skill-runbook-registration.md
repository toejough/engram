# 792g12 skill-runbook-registration - Adoption Audit

Audit of [792a12 skill-runbook-registration](../792a_product-spec.md#792a12-added-skill-runbook-registration) and the [792b](../792b_technical-spec.md) requirements whose `Supports:` lines cite its scenarios: [792b30 skill-source-discovery](../792b_technical-spec.md#792b30-added-skill-source-discovery) (792b30c1 to c17), [792b31 skill-registration-ledger](../792b_technical-spec.md#792b31-added-skill-registration-ledger) (792b31c1 to c8), [792b28c16 The registration step](../792b_technical-spec.md#792b28c16-the-registration-step), and the identity-field requirements [792b6c9 Skill identity fields](../792b_technical-spec.md#792b6c9-skill-identity-fields), [792b6c10 Rewrites by other writers keep the skill identity fields](../792b_technical-spec.md#792b6c10-rewrites-by-other-writers-keep-the-skill-identity-fields) and [792b12c7 Skill identity fields are not written by learn](../792b_technical-spec.md#792b12c7-skill-identity-fields-are-not-written-by-learn).

Method: read `internal/cli/skill*.go`, then ran the scenarios on a binary built from this tree (`go build -o /tmp/aud/bin/engram ./cmd/engram`) with HOME, XDG and `ENGRAM_VAULT_PATH` pointed at temp directories holding fake skill sources, plugins, Pi settings and repositories. Prompt scenarios ran under a pty. `engram update` clones the source and needs network and the large-file extension for the bundled model, so its scenarios were checked through their unit tests only.

Summary: 175 rows, 171 `match` and 4 `doc fixed`; no code bug and no row covered by #795/#796. The behavior matches the ported text almost everywhere. The divergences found were doc problems in [792b30c12 Pi settings reading and overrides](../792b_technical-spec.md#792b30c12-pi-settings-reading-and-overrides), [792b31c6 The registration run](../792b_technical-spec.md#792b31c6-the-registration-run) and [792a12i An existing runbook note can be adopted as a skill's note](../792a_product-spec.md#792a12i-an-existing-runbook-note-can-be-adopted-as-a-skills-note) (with a new scenario, 792a12i1j). Known code-side gaps are already tracked and were referenced, not refiled: #775 (scanner limits vs Pi), #777 (output polish: `@scope` with only removal offers prints the generic no-offer line, absolute source paths, silent explicit answers), #778 (file size), #779 (Pi and plugin edge cases), #781 (orphaned notes). New: #821 (Go comments cite the deleted OpenSpec design decisions D3, D4, R8; comment-only follow-up).
