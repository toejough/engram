## Summary

Rows by verdict: doc fixed 1, match 50. Total rows 51 (44 from 792a, 7 from 792b).

Every requirement and scenario of the write-memory capability was compared with `agent-instructions/skills/write-memory/SKILL.md` and with the flags the shipped binary accepts. The binary was built from this tree and driven against a temporary vault with HOME, XDG and ENGRAM_VAULT_PATH pointed at temporary directories.

- One doc fix: the tag form. The skill and the binary accept a bare `<family>` as well as `<family>/<value>`; the product spec named only the second.
- No code problem found. The scenario of a session that has only the runbook note is covered by the shim's follow-frame text but cannot be run on the binary.
- The ledger anchors cited by the capability's rationale (`write-memory-worker-fire-rates`, `write-memory-triggers-contract`) exist in dev/eval/LEDGER.md.
- Not covered here: vault initialization on a first write (#795).
- The ADR numbers cited in some rationales (for example ADR-0015) no longer resolve to a file in this tree; that is the final stale-reference sweep's concern and no text was changed for it.
