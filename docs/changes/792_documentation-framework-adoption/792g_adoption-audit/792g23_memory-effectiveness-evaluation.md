# 792g23 memory-effectiveness-evaluation - Adoption Audit

Audit of [792a23 memory-effectiveness-evaluation](../792a_product-spec.md#792a23-added-memory-effectiveness-evaluation) and the [792b38 eval-trial-harness](../792b_technical-spec.md#792b38-added-eval-trial-harness) and [792b39 memory-loop-auditor](../792b_technical-spec.md#792b39-added-memory-loop-auditor) requirements whose `Supports:` lines cite it. Method: read `dev/eval/isolation.py`, the three Python warm-configuration builders, the phase 2 probe and its fixtures, `dev/eval/traps/retrieval_probe.py`, `dev/eval/audit/audit_moments.py` and `generate_outcome_records.py`, and the Go `dev/eval/adapters.go`; ran the 724 offline unit tests of the touched files with pytest (all passed, no model call); reproduced the leak-guard window on temp directories; ran `derive_outcome_records` on synthetic moments in-process. No trial, audit or probe that calls a model, reads the real vault or reads real transcripts was run. Legacy sources recovered with `git show`: `eval-warm-config-fidelity`, `eval-trial-vault-leak-detection`, `eval-phase2-fixture-scoring-fidelity`, `retrieval-probe-signal-fidelity` (before 3b73d499) and `memory-loop-audit` plus its archived change (before 65c98016).

## Summary

79 rows: 52 match, 11 doc fixed, 16 code bug, 0 unclear. Four code problems were filed: [#824](https://github.com/toejough/engram/issues/824) (the leak guard scans only the last ten names alphabetically, so it usually misses a leaked note), [#825](https://github.com/toejough/engram/issues/825) (the audit never credits injected memories for fresh, workflow or Pi subagents, the orchestrator-side gap is always null, no paraphrase check), [#826](https://github.com/toejough/engram/issues/826) (the Go `targ eval` builder installs skills without checking SKILL.md) and [#827](https://github.com/toejough/engram/issues/827) (the ESTIMATE existence check never consults chunks). Doc fixes: the leak guard's scan window, the scope of the vault-guard and spawn-site requirements, the rebuild-skip claim, the runbook probe's failure behavior, a window's fields, how a reply is read, the ESTIMATE branch, and the outcome-record entry point; stale 500 KB wording in test docstrings was corrected. One item was `unclear` and is now a code bug: [#835](https://github.com/toejough/engram/issues/835) (792a23k1c: the calibration tolerance was never committed before the full run, and no gate requires it; Joe ruled it a bug, 2026-10-10). Out of the spec's scope but noted by 792d125 to 792d127: the Go harness's "malformed receipt counts as an outage" behavior is not a 792a23 requirement and was not traced.
