## 793bQ1 The summary is the last step of the burst that holds a turn's work: counts since the previous line, built from constants and counts only

- **Decided by:** Author (agent); awaiting owner validation. It applies [793b204 The memory-activity line is the mod's status line](#793b204-the-memory-activity-line-is-the-mods-status-line) to the mod without a runner and applies [793b297 Capture reads only what the user and the agent said, and the capture prompt and the delivered block frame content as data](#793b297-capture-reads-only-what-the-user-and-the-agent-said-and-the-capture-prompt-and-the-delivered-block-frame-content-as-data) to the one text the mod shows the user.
- **Choice:**
  - The mod keeps four counters (`summary.js`, `register.js`): items delivered (the notes a delivery carries, counted when the relevance judgement has chosen them, for the prompt, the route cue and a subagent alike), notes added (a lesson written by `engram learn`), notes amended (an offer settled as `near`, the one outcome that changes an existing note's claim; the reinforcing `amend --activate` of a covered lesson or a covered offer is not an amendment) and offers curated (an offer whose commands all ran, by any of the four outcomes). A step that fails counts nothing.
  - The line is shown once the queue is empty after a burst of jobs in which a top-level turn completed, after the housekeeping and before the seam's `idle` line, so that "the System's work for that turn has finished" holds when the harness reads it. A burst of subagent stops alone (a subagent that finishes between turns) adds to the counters and shows nothing; its counts are in the line of the next turn that completes. The counters are reset when the line is built, so each line counts what happened since the previous one, across the session and its subagents, and a prompt that arrives before the previous burst has finished is part of that burst.
  - The text is `Memory activity: ` followed by the non-zero counts in the order delivered, added, amended, curated, joined as `3 items delivered, 1 note added and 2 offers curated`, with singular nouns for 1. Nothing in it comes from a note, an offer, a lesson or a prompt: it is a constant, whole numbers the mod incremented, and the fixed words. A contract test feeds notes, lessons and prompts that hold hostile text and asserts that the line matches a character class that excludes any of it.
  - A turn with no count and no warning shows nothing. When it follows a turn whose line the System put on the status line, the System clears the line (`$.ui.status(undefined)`), so that a count is not read as this turn's after a quiet turn; when the System has put nothing there, it calls nothing.
- **Rationale:** [793a5h The user sees a summary of the memory activity](./793a_product-spec.md#793a5h-the-user-sees-a-summary-of-the-memory-activity) says one line after a turn, once the System's work for the turn is finished, nothing for an empty turn, counts since the previous summary. The tail of the queue is the one point at which the work of the turn is known to be finished ([793b301](#793b301-housekeeping-is-the-tail-of-the-queue-the-index-then-the-pending-offers-once-per-burst-of-jobs)). Counting `near` as the amendment follows 793b204's "not by a reinforcing activation".
- **Alternatives:** one line per job (several lines per turn, each replacing the last); showing the line at the top-level turn's own completion (the counts of its capture and housekeeping are not yet known); never clearing the line (a stale count stays on screen after a quiet turn).

## 793bQ2 The status line is one line: the warnings of the turn and the summary share it

- **Decided by:** Author (agent); awaiting owner validation. It answers the note "For the summary node" of [793b302 A failing step is classified, bounded by a named deadline and reported to the user on the status line](#793b302-a-failing-step-is-classified-bounded-by-a-named-deadline-and-reported-to-the-user-on-the-status-line).
- **Choice:** a warning is still shown at once, when its step fails (a lookup warning appears during the turn). The mod also keeps each distinct warning text (built from constants, 793b302) until the next line is shown; that line is the warnings, each once and in the order they happened, joined with `. `, then the summary if there is one (`Automatic memory was skipped because of an error (indexing). Memory activity: 1 note added`). A turn with a warning and no count shows the warning again as the whole line, so that a later call does not leave the user with less than they had. The warnings are forgotten when the line is shown. [793a4b](./793a_product-spec.md#793a4b-the-session-is-never-broken-or-stalled)'s scenarios read the warning with "some status message", which a line that carries it satisfies; the one existing contract test that listed the three messages of a turn lists the combined fourth line as well.
- **Rationale:** `$.ui.status` is one pinned line and a later call replaces it ([793b302](#793b302-a-failing-step-is-classified-bounded-by-a-named-deadline-and-reported-to-the-user-on-the-status-line)); [793a5h](./793a_product-spec.md#793a5h-the-user-sees-a-summary-of-the-memory-activity) puts both on the same surface; a summary shown alone after a failing capture would replace the only trace of the failure.
- **Alternatives:** the warning in a toast (it disappears after seconds, 793b204); a second status call that keeps the warning and drops the summary (the summary is the spec's line); two lines (the surface has one).
- **Amends:** [793b302](#793b302-a-failing-step-is-classified-bounded-by-a-named-deadline-and-reported-to-the-user-on-the-status-line) (3): the line after a turn carries the warnings of the turn.

## 793bQ3 How the node's scenarios are driven and read

- **Decided by:** Author (agent); awaiting owner validation. It changes how scenarios are driven, not their text.
- **Choice:**
  - A turn script may carry `seeds` (notes and offers put in the vault before the prompt, through the existing real paths: `engram learn`, and the serve write path of SP10, with a near offer that states a note's claim and one more) and `settle` (the step waits for the System's idle line after the turn, as a user reads the line before typing the next prompt). The Givens of the product text name no note or offer for the summary scenarios, so the event in the quoted phrase is made to happen by the script: [793a5h1a](./793a_product-spec.md#793a5h1-uat-scenarios) seeds three notes on one situation, a near offer and an absent offer, and dispatches a subagent that is told a rule. The counts of it depend on the relevance, capture and curation judgements; a red result there is read first as a judgement miss ([793e2g Risks](./793e_implementation-plan.md#793e2g-risks)).
  - "The user is shown a one-line summary with COUNTS" reads the `ui_status` messages of the stream: some line contains the counts; for `and no other count` some line ends with exactly those counts. "Shown no memory-activity summary" holds when no line holds the summary prefix. "Appears nowhere in the transcript or in the working agent's next response" requires that a summary was shown, then that no row of the main or a subagent transcript holds the prefix or a line the user was shown, and that the final reply does not.
  - "Every note written by the agent's own memory command is still in the vault": the paths that `engram learn` printed in the results of the agent's own commands (read from the transcript) all exist once the System's work is idle; a scenario can require that there is at least one (`agentWrites`).
  - [793a5c1a Unsupported harness](./793a_product-spec.md#793a5c1-uat-scenarios) is observed in a Claude Code home to which `engram update` was never run: the install tree is what it was, the session's loaded plugins do not include the mod, the System added no row to the transcript and showed no status line, and the seam file was never written. [793a5c1b](./793a_product-spec.md#793a5c1-uat-scenarios) ends `Not run` at its first Given (SP14: no headless Pi); no fixture stands in.
- **Rationale:** [793b246](#793b246-assertions-read-the-transcript-the-vault-and-a-harness-only-seam-log-only-preconditions-are-retried) asks for outcomes read from what the System left; [793b264](#793b264-results-include-substituted-and-pi-agent-behaviour-is-not-faked-with-fixtures) forbids a fixture for a Pi agent's behaviour.
- **Alternatives:** counts asserted from independent evidence instead of the literal in the scenario (it would not test the text); a settle in every turn step (it would hide the case of a prompt that arrives while the System is still working, which [793a4j1e](./793a_product-spec.md#793a4j1-uat-scenarios) needs).
